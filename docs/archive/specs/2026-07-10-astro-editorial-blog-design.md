# Astro 未来编辑部风个人博客设计

## 目标

在 `D:\astro-blog` 创建一个可本地运行、可部署到 GitHub Pages 的现代个人博客骨架。项目参考 `kizzy899.github.io` 的内容组织方式，但不复制其 Hexo/Butterfly 界面，改用更现代的未来编辑部视觉和 Astro 技术栈。

第一版的成功标准：访客能浏览首页、文章列表、文章详情、归档、标签和关于页面；作者能通过新增 Markdown/MDX 文件发布文章；生产构建可以生成完整静态站点。

## 技术架构

- Astro、TypeScript 和 Astro Content Collections。
- Markdown/MDX 保存文章，Frontmatter 包含标题、摘要、发布日期、更新时间、标签、封面、是否置顶和草稿状态。
- 原生 CSS 与少量客户端 JavaScript，避免引入完整 UI 框架。
- 页面默认静态生成，构建输出目录为 `dist/`。
- GitHub Actions 使用 Astro 官方 Pages Action 自动构建和部署。

## 视觉方向

整体采用“未来编辑部”风格，而不是传统博客主题：

- 大字号无衬线标题与小号等宽元信息形成对比。
- 非对称十二列网格、跨列文章卡片和杂志式编号。
- 主色为纸白/墨黑，强调色使用高饱和电光橙或酸性绿色；颜色由语义化 CSS Token 管理。
- 图片使用大幅裁切、细边框和轻微颗粒纹理，不使用厚重玻璃拟态。
- 动效集中在页面切换、滚动揭示、图片遮罩和链接状态，持续时间控制在 150–350ms。
- 深色模式保持同一编辑部气质，不简单反转颜色。
- 尊重 `prefers-reduced-motion`，键盘焦点清晰，正文对比度满足 WCAG AA。

## 页面与组件

### 首页

- 顶部品牌标识、主导航、搜索入口和主题切换。
- 杂志封面式 Hero：站点名称、短介绍、当前期号与精选文章。
- 不规则网格展示精选文章和最近文章。
- 技术主题/标签索引和简短作者介绍。

### 内容页

- `/posts/`：全部文章，可按标签筛选。
- `/posts/[slug]/`：文章标题、元信息、封面、正文、目录、阅读进度、代码复制、上一篇/下一篇。
- `/archive/`：按年份和月份排列的时间轴。
- `/tags/` 与 `/tags/[tag]/`：标签总览和单标签文章列表。
- `/about/`：作者介绍、技术栈和联系方式占位内容。
- `/404`：延续编辑部排版的错误页面。

### 复用组件

- `SiteHeader`、`SiteFooter`、`ThemeToggle`、`SearchDialog`。
- `HeroFeature`、`PostCard`、`TagChip`、`ArticleMeta`。
- `TableOfContents`、`ReadingProgress`、`CodeCopyButton`。

每个组件只承担一个明确职责；页面负责组合，内容查询集中在独立工具模块中。

## 内容流

1. 作者在内容目录新增 Markdown/MDX。
2. Content Collections 在开发和构建阶段校验 Frontmatter。
3. 内容工具模块过滤草稿、按日期排序，并生成归档与标签数据。
4. Astro 为文章及标签生成静态路径。
5. GitHub Actions 构建 `dist/` 并部署到 GitHub Pages。

## 第一版示例内容

提供三篇中文示例文章，分别展示普通正文、代码块、图片、引用、表格和标签。所有站点名称、作者、简介、社交链接与部署地址集中配置，方便后续替换。

## 异常与边界处理

- Frontmatter 缺少必填字段时构建失败并显示明确错误。
- 草稿不会进入生产文章列表、标签、归档或站点地图。
- 缺少封面时使用编辑部风格的排版占位卡，而不是破图。
- 搜索采用构建时生成的轻量索引；无结果时提供清晰反馈。
- 长标题、超长代码、中文标签和窄屏设备不得产生横向页面滚动。

## 验证

- 运行类型检查和 Astro 构建。
- 检查首页、文章页、标签页、归档页、关于页和 404 的生成结果。
- 在 375px 手机宽度与常见桌面宽度检查布局。
- 验证键盘导航、可见焦点、深浅色模式和减少动态效果偏好。
- 确认内部链接、代码复制和搜索的基本行为。

## 暂不包含

第一版不加入后台管理、数据库、账号系统、评论服务、访问统计和第三方图床。这些功能可以在骨架确认后按需增加，避免过早扩大范围。
