这周整体可以分成三部分：PostgreSQL 的学习和升级计划、项目实时交互体验的优化，以及数据结构与算法的系统复习。

先说 PostgreSQL。

这部分目前不只是停留在了解语法，而是在为后续项目数据库升级做准备。因为现在项目里有任务、分析结果、进度状态、事件记录这类数据，后面随着功能增加，数据之间的关联、查询复杂度和扩展性都会越来越重要，所以我计划把 PostgreSQL 纳入项目的升级方案。

这几天主要学习和练习了 PostgreSQL 的基础数据操作，包括建表、插入、查询、修改、删除、条件筛选、排序和分页。比如在新增或更新数据时，PostgreSQL 的 `RETURNING` 可以直接返回刚写入或修改后的记录，这样接口层可以少一次额外查询，处理任务创建、状态更新这类场景会更方便。

- 项目本身是一个视频检测项目。用户上传视频后，系统会经过任务创建、视频处理、模型检测、结果生成这些步骤，最后返回的数据本身就是 JSON 格式。里面可能包括任务 ID、视频信息、检测到的事件、目标类别、置信度、时间段、坐标位置、统计信息，以及后续模型可能新增的字段。

  所以我考虑 PostgreSQL，最核心的原因就是它的 JSONB 类型比较适合这种“主体结构相对固定，但检测结果字段可能不断扩展”的场景。

  MySQL 也支持 JSON，但 PostgreSQL 的 JSONB 在项目里会更有优势。JSONB 会把 JSON 按更适合查询的二进制形式存储，支持对内部字段做查询、包含判断和索引。比如后续可以直接在数据库里筛选“检测结果中包含某个目标类别”“置信度高于某个值”“视频里出现过某类事件”的任务，而不需要每次把完整 JSON 取回到后端再解析过滤。

所以 PostgreSQL 这部分目前的定位是：先把能力补齐，再结合项目现有的 MySQL 数据结构、业务查询和部署方式，制定迁移方案。
接下来是学习PostgreSQL中的一些实操。


## 增删改查、条件、排序和分页

向商品表中添加商品，并查询、修改和删除商品。

### 插入数据

```
INSERT INTO products (name, price, stock, description)
VALUES
    ('机械键盘', 299.00, 50, '有线机械键盘'),
    ('无线鼠标', 99.90, 120, '人体工学无线鼠标'),
    ('显示器', 1299.00, 30, '27 英寸显示器'),
    ('USB-C 数据线', 39.90, 300, '支持快速充电')
RETURNING *;
```

```
INSERT INTO products (...)
```

指定要写入的字段。

没有指定的字段会使用默认值：

```
id          自动生成
is_active   默认 true
created_at  默认当前时间
RETURNING *
```

返回刚刚插入的数据，这是 PostgreSQL 很实用的特性。

### MySQL 对比

MySQL 的插入方式基本相同：

```
INSERT INTO products (name, price, stock)
VALUES ('机械键盘', 299.00, 50);
```

但 MySQL 通常需要再执行查询获取自增 ID：

```
SELECT LAST_INSERT_ID();
```

PostgreSQL 可以直接：

```
INSERT ...
RETURNING id;
```

### 查询、排序和分页

```
SELECT
    name,
    price,
    stock
FROM products
WHERE price >= 100
  AND stock > 0
ORDER BY price DESC
LIMIT 2 OFFSET 0;
```

代码含义：

```
WHERE      过滤数据
ORDER BY   排序
LIMIT      每页返回多少条
OFFSET     跳过多少条
```

第 2 页、每页 2 条：

```
LIMIT 2 OFFSET 2;
```

### 修改数据

```
UPDATE products
SET price = price * 0.9
WHERE name = '显示器'
RETURNING *;
```

执行前建议先查询：

```
SELECT *
FROM products
WHERE name = '显示器';
```

这样可以避免更新错误的数据。

### 删除数据

```
DELETE FROM products
WHERE stock = 0
RETURNING *;
```

**`DELETE` 如果不写 `WHERE`，会删除整张表的数据：**

```
DELETE FROM products;
```

### MySQL 对比

`SELECT`、`UPDATE`、`DELETE` 的基础语法和 MySQL 基本一致，差异主要在：

```
PostgreSQL 支持 RETURNING
MySQL 通常需要额外 SELECT
PostgreSQL 使用 ILIKE 进行不区分大小写匹配
```

## 聚合、GROUP BY、HAVING 和 WITH

### 聚合查询

```
SELECT
    COUNT(*) AS product_count,
    SUM(stock) AS total_stock,
    AVG(price) AS average_price,
    MIN(price) AS min_price,
    MAX(price) AS max_price
FROM products;
```

常用聚合函数：

```
COUNT()  统计数量
SUM()    求和
AVG()    平均值
MIN()    最小值
MAX()    最大值
```

### 分组统计

```
SELECT
    is_active,
    COUNT(*) AS product_count,
    AVG(price) AS average_price,
    SUM(stock) AS total_stock
FROM products
GROUP BY is_active;
```

这会分别统计：

```
上架商品
未上架商品
```

### HAVING

查询平均价格超过 100 的分组：

```
SELECT
    is_active,
    COUNT(*) AS product_count,
    AVG(price) AS average_price
FROM products
GROUP BY is_active
HAVING AVG(price) > 100;
```

区别：

```
WHERE   过滤分组前的行
HAVING  过滤分组后的结果
```

### WITH

先筛选价格大于 100 的商品，再进行统计：

```
WITH expensive_products AS (
    SELECT *
    FROM products
    WHERE price > 100
)
SELECT
    COUNT(*) AS product_count,
    SUM(stock) AS total_stock
FROM expensive_products;
```

`WITH` 可以把复杂查询拆成多个有名字的步骤，更容易阅读和维护。

### MySQL 对比

MySQL 也支持：

```
COUNT
SUM
AVG
GROUP BY
HAVING
WITH
```

基础语法基本一致，但 PostgreSQL 对 SQL 标准和分组规则通常更加严格。

## 约束、JOIN 和子查询

### 创建分类表

```
CREATE TABLE categories (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name text NOT NULL UNIQUE,
    description text
);
```

插入分类：

```
INSERT INTO categories (name, description)
VALUES
    ('键鼠设备', '键盘和鼠标'),
    ('显示设备', '显示器等设备'),
    ('线材配件', '数据线和其他配件');
```

### 给商品表增加分类字段

```
ALTER TABLE products
ADD COLUMN category_id bigint;
```

给商品设置分类：

```
UPDATE products
SET category_id =
    CASE
        WHEN name IN ('机械键盘', '无线鼠标') THEN 1
        WHEN name = '显示器' THEN 2
        ELSE 3
    END;
```

### 建立外键

```
ALTER TABLE products
ADD CONSTRAINT products_category_fk
FOREIGN KEY (category_id)
REFERENCES categories(id);
```

这表示：

```
products.category_id
必须引用
categories.id
```

如果插入不存在的分类 ID：

```
INSERT INTO products (name, price, stock, category_id)
VALUES ('测试商品', 10, 10, 999);
```

数据库会拒绝这条数据。

### MySQL 对比

MySQL 外键写法基本一致：

```
ALTER TABLE products
ADD CONSTRAINT products_category_fk
FOREIGN KEY (category_id)
REFERENCES categories(id);
```

主要差别在于 PostgreSQL 更常使用：

```
text
identity
boolean
numeric
```

而 MySQL 常见：

```
varchar
auto_increment
tinyint(1)
decimal
```

### INNER JOIN

查询商品和分类：

```
SELECT
    p.name AS product_name,
    p.price,
    c.name AS category_name
FROM products AS p
INNER JOIN categories AS c
    ON p.category_id = c.id;
```

执行过程：

```
读取 products
→ 使用 category_id 匹配 categories.id
→ 返回商品和分类信息
```

### LEFT JOIN

查询所有分类，即使分类下没有商品：

```
SELECT
    c.name AS category_name,
    p.name AS product_name
FROM categories AS c
LEFT JOIN products AS p
    ON p.category_id = c.id;
```

区别：

```
INNER JOIN：只返回匹配成功的数据
LEFT JOIN：左表数据全部保留
```

### 子查询

查询价格高于平均价格的商品：

```
SELECT
    name,
    price
FROM products
WHERE price > (
    SELECT AVG(price)
    FROM products
);
```

内部查询先计算平均价格，外部查询再使用这个结果。

## PostgreSQL 特色能力

### 一、RETURNING

```
UPDATE products
SET price = price * 0.9
WHERE name = '机械键盘'
RETURNING id, name, price;
```

作用：

```
修改数据
→ 立即返回修改后的数据
```

MySQL 通常需要修改后再次执行：

```
SELECT id, name, price
FROM products
WHERE name = '机械键盘';
```

### 二、ON CONFLICT

创建测试表：

```
CREATE TABLE feature_demo (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name text NOT NULL UNIQUE,
    tags text[] NOT NULL DEFAULT '{}',
    metadata jsonb NOT NULL DEFAULT '{}'
);
```

插入数据：

```
INSERT INTO feature_demo (name, tags, metadata)
VALUES (
    '机械键盘',
    ARRAY['办公', '有线'],
    '{"brand": "Keychron", "layout": "87键"}'::jsonb
)
RETURNING *;
```

再次插入同名商品时：

```
INSERT INTO feature_demo (name, tags, metadata)
VALUES (
    '机械键盘',
    ARRAY['办公', '无线'],
    '{"brand": "Keychron", "wireless": true}'::jsonb
)
ON CONFLICT (name)
DO UPDATE SET
    tags = EXCLUDED.tags,
    metadata = EXCLUDED.metadata
RETURNING *;
```

`EXCLUDED` 表示本次准备插入的数据。

### MySQL 对比

PostgreSQL：

```
ON CONFLICT (name)
DO UPDATE SET ...
```

MySQL：

```
ON DUPLICATE KEY UPDATE ...
```

两者都是 Upsert，但语法不同。

### 三、数组

插入标签：

```
INSERT INTO feature_demo (name, tags)
VALUES (
    '无线鼠标',
    ARRAY['办公', '无线', '人体工学']
);
```

查询包含“无线”标签的数据：

```
SELECT *
FROM feature_demo
WHERE '无线' = ANY(tags);
```

PostgreSQL 原生支持数组，MySQL 一般需要使用 JSON 或单独的关联表实现。

### 四、JSONB

插入 JSONB 数据：

```
INSERT INTO feature_demo (name, metadata)
VALUES (
    '显示器',
    '{"brand": "Dell", "size": 27, "resolution": "2K"}'::jsonb
);
```

读取 JSON 字段：

```
SELECT
    name,
    metadata ->> 'brand' AS brand
FROM feature_demo;
```

查询品牌：

```
SELECT *
FROM feature_demo
WHERE metadata ->> 'brand' = 'Dell';
```

操作符：

```
->   返回 JSON
->>  返回文本
@>   判断 JSON 是否包含指定内容
```

MySQL 也支持 JSON，但 PostgreSQL 的 `jsonb` 通常更适合查询和建立索引。

### 五、UUID

```
SELECT id, name
FROM feature_demo;
```

UUID 适合：

```
分布式系统
跨服务数据交互
不希望暴露连续自增 ID 的场景
```

但 UUID 比整数更大，索引和排序成本也更高。



## 项目优化

第二部分是项目升级。

项目当前的一个核心体验问题，是用户提交分析任务后，前端只能看到比较粗糙的“处理中”状态，用户不知道任务具体执行到哪里了、是不是卡住了、网络断开后有没有继续处理。针对这个问题，我主要围绕“任务实时进度”和“前端任务中心交互”做了升级。

首先是实时任务进度这一块。

现在把 Worker、API 和前端之间的状态链路重新梳理了一下。Worker 在执行任务时，会把任务所处的阶段、进度百分比、状态消息和异常信息通过 Redis 进行传递；API 再通过 SSE，也就是服务端实时推送，把这些内容持续发送给前端。

这样用户在前端看到的不再只是一个静态状态，而是可以实时看到任务正在检测、分析、收尾，还是已经完成或失败。页面会有进度条、阶段文本和状态说明，用户能更明确地知道系统当前正在做什么。

其次是断线重连和状态一致性。

实时系统里比较容易出问题的地方，是网络断开、页面刷新、重复消息和旧状态覆盖新状态。针对这些情况，增加了快照校准、消息序号和任务尝试次数的处理。

简单来说，用户页面断线重连后，不是只继续接收后面的新消息，而是会先根据服务端保存的最新任务快照把当前状态校准回来；这样即使中间漏掉了一些实时事件，前端也不会一直停留在旧进度。


第三是任务状态的可靠性。

之前需要特别注意一个问题：任务实际上还没有成功写入数据库，但前端已经提前收到“完成”或“失败”的消息，这就会造成页面状态和实际数据不一致。现在把流程调整为，任务的最终状态必须在数据库持久化成功后，才能发布给前端。

这样能保证用户看到“任务已完成”时，对应的分析结果和任务状态确实已经可以查询到。失败时也尽量保留真实失败阶段和具体原因，而不是用一个比较模糊的统一状态代替，后续排查和用户理解都会更清晰。

前端交互层面，也对任务中心做了比较完整的优化。

现在任务卡片会展示任务状态、当前阶段、实时进度、状态消息和错误信息。用户点击任务后，可以在详情抽屉里继续查看实时任务信息；如果任务已经完成，也可以查看事件详情和播放分析结果。即使某些任务没有单独事件，但任务级视频已经生成，前端也会提供播放入口。

另外还增加了任务状态筛选、按更新时间排序、删除后状态同步等处理，避免任务删掉以后又因为轮询或实时消息重新出现在列表里。


## 数据结构与算法

上周重新复习的数据结构，本周学习计划打算使用Rust语言进行一轮学习和实操，从而巩固方面的知识。

### 数组

**1. 一维数组**

Rust 中的固定长度数组使用 `[T; N]` 表示：

```
let nums: [i32; 5] = [10, 20, 30, 40, 50];
```

数组的特点：

- 长度固定
- 元素类型相同
- 内存连续
- 可以通过下标快速访问

访问数组元素时，程序可以直接根据起始地址和下标计算位置，因此时间复杂度是 O(1)。

但是，查找某个值时，如果数组没有排序，就需要从头到尾遍历：

```
 for i in 0..nums.len() {
        if nums[i] == target {
            return Some(i);
```

所以最好情况是O(1)最坏是O(n)，平均就是O(n)。

**二维数组**

二维数组可以理解为“数组中的数组”，常用于表示矩阵、棋盘和地图。

访问二维数组需要两个下标：``` matrix[行][列]``` ,遍历二维数组通常使用嵌套循环：

```
 for row in matrix {
        for value in row {
            print!("{} ", value);
        }
```

**动态数组 Vec**

固定数组的长度不能改变。如果需要动态增加或删除元素，通常使用 `Vec<T>`。

常见操作

```
 nums.push(40);       // 末尾添加
    nums.pop();          // 删除末尾元素
    nums[0] = 100;       // 修改元素
    nums.insert(1, 200); // 在指定位置插入
    nums.remove(2);      // 删除指定位置元素
```

**二分查找**

二分查找适用于**有序数组**。其首先比较数组中间的元素与目标值：如果目标值与该元素匹配，则返回其在数组中的位置；如果目标值小于该元素，则在数组较小的那一半中继续查找；如果目标值大于该元素，则在数组较大的那一半中继续查找。通过这种方法，每次迭代都能将搜索范围缩小一半。

给定一个包含 n 个元素的有序数组 A，其中元素满足：

A[0] <= A[1] <= A[2] <= ... <= A[n - 1]

假设目标值为 T，使用二分查找寻找 T 在数组中的索引。

1. 初始化 L = 0，R = n - 1。

2. 如果 L > R，则查找失败，结束查找。

3. 计算中间位置：

   m = (L + R) / 2

   这里使用向下取整。

4. 如果 A[m] < T，则令 L = m + 1，返回第 2 步。

5. 如果 A[m] > T，则令 R = m - 1，返回第 2 步。

6. 如果 A[m] == T，则查找成功，返回索引 m。

在Rust中实现：

```
fn binary_search(nums: &[i32], target: i32) -> Option<usize> {
    let mut left = 0;
    let mut right = nums.len();

    while left < right {
        let mid = left + (right - left) / 2;

        if nums[mid] == target {
            return Some(mid);
        } else if nums[mid] < target {
            left = mid + 1;
        } else {
            right = mid;
        }
    }

    None
}
```

数组擅长快速访问，但不擅长中间插入和删除；如果数组有序，可以使用二分查找将查找复杂度从 O(n) 降低到 O(log n)。**必须前提是数组必须已经有序**。

### 链表

数组把元素连续存放在内存中，而链表中的节点可以分散在内存的不同位置，再通过指针或引用将它们连接起来。

每个节点包含两部分：

- 数据
- 指向下一个节点的链接

最后一个节点没有下一个节点，因此通常用 `null` 表示。

数组的优点是可以通过下标快速访问，但数组中间插入元素时，需要移动后面的数据，链表不需要移动其他节点，只需要修改节点之间的连接关系。

因此：

- 数组适合快速访问
- 链表适合频繁插入和删除

在Rust中定义：

```
struct Node {
    value: i32,
    next: Option<Box<Node>>,
}
```

遍历链表时，需要从头节点开始，沿着 `next` 逐个访问。查找同理链表无法像数组通过下标直接定位元素，因此查找需要从头到尾的遍历。所以时间复杂度也是O(n)。

```
impl LinkedList {
    fn contains(&self, target: i32) -> bool {
        let mut current = self.head.as_deref();

        while let Some(node) = current {
            if node.value == target {
                return true;
            }

            current = node.next.as_deref();
        }

        false
    }
}	
```

### 栈和队列

栈和队列都是线性数据结构，但它们对数据的访问顺序不同：

- 栈：后进先出，LIFO
- 队列：先进先出，FIFO

本质上就是在单向链表的基础上实现栈和队列，因为栈和队列都可以使用链表作为底层结构。

Rust 中可以使用 `Vec<T>` 实现栈。

```
impl<T> Stack<T> {
    fn new() -> Self {
        Self {
            data: Vec::new(),
        }
    }
}
```

栈有个经典的实际应用：括号匹配。匹配规则如下：

- 遇到左括号，入栈
- 遇到右括号，检查是否与栈顶左括号匹配
- 最后栈必须为空

在Rust中实现：

```fn is_valid_brackets(s: &str) -> bool {
    fn is_valid_brackets(s: &str) -> bool {
    let mut stack = Vec::new();

    for ch in s.chars() {
        match ch {
            '(' | '[' | '{' => {
                stack.push(ch);
            }
            ')' | ']' | '}' => {
                let Some(top) = stack.pop() else {
                    return false;
                };

                let matched = matches!(
                    (top, ch),
                    ('(', ')') | ('[', ']') | ('{', '}')
                );

                if !matched {
                    return false;
                }
            }
            _ => {}
        }
    }

    stack.is_empty()
}
```

**队列**

队列从一端加入元素，从另一端删除元素。队列通常有两个位置：

- 队首：删除元素的位置
- 队尾：添加元素的位置

```
struct Queue<T> {

}
```

**哈希表与集合**

哈希表是实际开发中非常重要的数据结构，常用于：

- 根据 ID 查找对象
- 统计元素出现次数
- 数据去重
- 缓存
- 判断某个元素是否存在
- 实现集合和映射

Rust 中常用的哈希结构包括：

```
HashMap<K, V>
HashSet<T>
```

哈希表通常由以下几部分组成：

1. 底层数组
2. 哈希函数
3. 哈希桶
4. 冲突解决机制

例如：

```
key = "apple"

hash("apple") = 123456

123456 % 数组长度 = 3
```

于是可以把 `"apple"` 存储到下标 3 的位置。

```
下标：  0    1    2    3
数据： null null null apple
```

之后查找 `"apple"` 时，再次计算哈希值，就能快速定位到下标 3。

**哈希冲突**

不同的 key 可能计算出相同的数组下标。

例如：

```
hash("apple") % 10 = 3
hash("banana") % 10 = 3
```

这就产生了哈希冲突。

哈希冲突无法完全避免，只能通过合理设计来解决。

**1. 链地址法**

每个数组位置保存多个元素。

```
下标 3 -> ("apple", 100) -> ("banana", 200)
```

发生冲突时，将元素添加到同一个桶中。

**2. 开放地址法**

如果目标位置已经被占用，就寻找其他空位置。

常见方法包括：

- 线性探测
- 二次探测
- 双重哈希

例如，原本想放到下标 3，但下标 3 已被占用，就尝试下标 4、5、6。

**负载因子和扩容**

负载因子表示哈希表中元素数量与数组容量的比例：

```
负载因子 = 元素数量 / 数组容量
```

如果负载因子过高，冲突会增加，查询效率会下降。

例如：

```
元素数量：8
数组容量：10
负载因子：0.8
```

当元素过多时，哈希表通常会进行扩容：

1. 创建更大的底层数组。
2. 重新计算所有元素的位置。
3. 将元素迁移到新数组。

扩容本身需要 O(n) 时间，但不是每次插入都会发生，因此插入操作的均摊复杂度通常仍然是 O(1)。

**使用 entry 统计次数**

统计字符串中每个单词出现的次数，是哈希表的经典应用。

```
use std::collections::HashMap;

fn count_words(words: &[&str]) -> HashMap<String, usize> {
    let mut counter = HashMap::new();

    for word in words {
        let count = counter.entry((*word).to_string()).or_insert(0);
        *count += 1;
    }

    counter
}

fn main() {
    let words = ["rust", "go", "rust", "python", "go", "rust"];

    let result = count_words(&words);

    println!("{:?}", result);
}
```

**使用 HashMap 查找两数之和**

给定一个数组和目标值，找出两个数之和等于目标值的下标。

```use std::collections::HashMap;
fn two_sum(nums: &[i32], target: i32) -> Option<(usize, usize)> {
    let mut map = HashMap::new();

    for (index, &value) in nums.iter().enumerate() {
        let needed = target - value;

        if let Some(&previous_index) = map.get(&needed) {
            return Some((previous_index, index));
        }

        map.insert(value, index);
    }

    None
}

fn main() {
    let nums = [2, 7, 11, 15];

    println!("{:?}", two_sum(&nums, 9));
}
```

**HashSet 集合**

`HashSet<T>` 用于保存**不重复**的数据。

所以最常用的功能就是去重

```
use std::collections::HashSet;

fn remove_duplicates(nums: &[i32]) -> Vec<i32> {
    let mut seen = HashSet::new();
    let mut result = Vec::new();

    for &num in nums {
        if seen.insert(num) {
            result.push(num);
        }
    }

    result
}

```

**HashMap 和 HashSet 的复杂度**

平均情况下：

| 操作 | HashMap | HashSet |
| ---- | ------- | ------- |
| 插入 | O(1)    | O(1)    |
| 查找 | O(1)    | O(1)    |
| 删除 | O(1)    | O(1)    |

最坏情况下，如果大量 key 发生哈希冲突，操作可能退化为 O(n)。

实际使用中，哈希函数、扩容策略和冲突解决机制会影响性能。

**什么时候使用哈希表**

适合使用哈希表的场景：

- 根据 key 快速查找 value
- 统计频率
- 判断元素是否出现过
- 数据去重
- 缓存数据
- 建立索引
- 两数之和
- 判断数组中是否存在重复元素

不适合使用哈希表的场景：

- 需要数据有序
- 需要频繁范围查询
- 需要按照大小关系遍历
- 需要查找最小值或最大值

这些场景可以考虑平衡树、堆或排序数组。

### 递归与分治

前面学习的快速排序和归并排序都使用了递归，后面学习二叉树遍历、DFS、回溯和动态规划时，也会频繁用到递归。

**递归的三个要素**

一个完整的递归函数通常包含三个部分：

**1. 终止条件**

也叫递归出口，用来停止递归。

```
if n == 0 {
    return 1;
}
```

**2. 递归调用**

函数调用自己。

```
factorial(n - 1)
```

**3. 问题规模变小**

每次递归调用都应该让问题规模变小，否则可能无限递归。

```
n - 1
```

小例子递归阶乘：

```
fn factorial(n: u64) -> u64 {
    if n == 0 {
        return 1;
    }

    n * factorial(n - 1)
}
```

**递归调用栈**

每次调用函数时，系统都会保存当前函数的执行状态。

例如：

```
factorial(5)
factorial(4)
factorial(3)
factorial(2)
factorial(1)
```

这些调用会依次进入调用栈。

当到达终止条件后，再从栈顶开始逐层返回：

```
factorial(1) 返回 1
factorial(2) 返回 2
factorial(3) 返回 6
factorial(4) 返回 24
factorial(5) 返回 120
```

因此，递归太深时可能导致栈溢出。

**什么是分治**

分治的全称是“分而治之”。

它的基本思想是：

1. 将一个大问题拆分成多个规模更小的子问题。
2. 分别解决这些子问题。
3. 将子问题的结果合并起来。

```
大问题
  ↓
拆分成多个小问题
  ↓
分别解决
  ↓
合并结果
```

快速排序和归并排序都是分治算法。

### 二叉树

树是一种具有层级关系的数据结构。二叉树是树结构中最常见的一种。

二叉树的特点是：

> 每个节点最多拥有两个子节点。

这两个子节点分别叫：

- 左子节点
- 右子节点

**二叉树的基本概念**

**根节点**

树的最顶层节点。

```
        1
```

这里的 `1` 就是根节点。

**叶子节点**

没有任何子节点的节点。

```
4、5、3
```

都是叶子节点。

**深度**

某个节点距离根节点的边数。

```
根节点 1：深度 0
节点 2：深度 1
节点 4：深度 2
```

**高度**

从某个节点到最深叶子节点的最长路径。

整个树的高度是 2。

------

**二叉树的几种类型**

**满二叉树**

每个节点要么有 0 个子节点，要么有 2 个子节点。

```
        1
       / \
      2   3
     / \
    4   5
```

**完全二叉树**

除了最后一层之外，其他层都填满，并且最后一层的节点从左到右排列。

```
        1
       / \
      2   3
     / \  /
    4  5 6
```

堆就是一种完全二叉树。

**平衡二叉树**

左右子树的高度差不会太大。

平衡树的查找效率通常较高。

**退化二叉树**

如果每个节点只有一个子节点，就会退化成类似链表的结构：

```
1
 \
  2
   \
    3
     \
      4
```

在Rust手搓一颗二叉树试试：


**二叉树的深度优先遍历**

二叉树常见的深度优先遍历有三种：

- 前序遍历
- 中序遍历
- 后序遍历

它们的区别在于访问根节点的时机不同。

**1. 前序遍历**

顺序是：

```
根节点 -> 左子树 -> 右子树
```

```fn preorder(root: &Option<Box<TreeNode>>, result: &mut Vec<i32>) {
 fn preorder(root: &Option<Box<TreeNode>>, result: &mut Vec<i32>) {
    let Some(node) = root else {
        return;
    };

    result.push(node.value);
    preorder(&node.left, result);
    preorder(&node.right, result);
}
```

前序遍历常用于：

- 复制树
- 序列化树
- 生成目录结构
- 表达式树处理

**中序遍历**

顺序是：

```
左子树 -> 根节点 -> 右子树
```

```
fn inorder(root: &Option<Box<TreeNode>>, result: &mut Vec<i32>) {
    let Some(node) = root else {
        return;
    };

    inorder(&node.left, result);
    result.push(node.value);
    inorder(&node.right, result);
}
```

中序遍历在二叉搜索树中非常重要：

> 对二叉搜索树进行中序遍历，可以得到升序结果。

**后序遍历**

顺序是：

```
左子树 -> 右子树 -> 根节点
```

```
fn postorder(root: &Option<Box<TreeNode>>, result: &mut Vec<i32>) {
    let Some(node) = root else {
        return;
    };

    postorder(&node.left, result);
    postorder(&node.right, result);
    result.push(node.value);
}
```

后序遍历常用于：

- 删除树
- 计算目录大小
- 表达式求值
- 计算树的高度

**计算二叉树的节点数量**

可以使用递归计算节点数量：

```
fn count_nodes(root: &Option<Box<TreeNode>>) -> usize {
    let Some(node) = root else {
        return 0;
    };

    1 + count_nodes(&node.left) + count_nodes(&node.right)
}
```

计算逻辑：

```
当前节点数量
= 1
+ 左子树节点数量
+ 右子树节点数量
```

**计算二叉树高度**

```
fn tree_height(root: &Option<Box<TreeNode>>) -> usize {
    let Some(node) = root else {
        return 0;
    };

    let left_height = tree_height(&node.left);
    let right_height = tree_height(&node.right);

    1 + left_height.max(right_height)
}
```

计算逻辑：

```
树的高度
= 1 + max(左子树高度, 右子树高度)
```

**二叉搜索树**

二叉搜索树（binary search tree）是一种有根二叉树数据结构。它要求每个内部节点的键值都大于其左子树中所有节点的键值，且都小于其右子树中所有节点的键值。该树各项操作时间复杂度均与树的高度成线性关系。

二叉搜索树每次比较都能排除大约一半的剩余节点，故能以对数时间查找、插入、删除数据。但其性能依赖于节点的插入顺序，插入随机键值时仍能维持对数级别，但在最坏情况下会退化成链表。为保证效率，研究者发明了多种平衡树，能将最坏查找复杂度维持在 O ( log ⁡ n ) 。 

二叉搜索树除了满足二叉树的结构，还要求：**左边小，右边大**。

遍历方式和二叉树一致知识需要满足要求结构!

**深度优先搜索 DFS**

深度优先搜索算法（Depth-First-Search）是一种用于遍历或搜索树或图的算法。这个算法会尽可能深地搜索树的分支。当节点v的所在边都己被探寻过，搜索将回溯到发现节点v的那条边的起始节点。这一过程一直进行到已发现从源节点可达的所有节点为止。如果还存在未被发现的节点，则选择其中一个作为源节点并重复以上过程，整个进程反复进行直到所有节点都被访问为止。这种算法不会根据图的结构等信息调整执行策略。

深度优先搜索是图论中的经典算法，利用深度优先搜索算法可以产生目标图的拓扑排序表，利用拓扑排序表可以方便的解决很多相关的图论问题，如无权最长路径问题等等。 

Rust递归实现DFS：

```
impl Graph {
    fn dfs(&self, start: usize) -> Vec<usize> {
        let mut visited = vec![false; self.adj.len()];
        let mut result = Vec::new();

        fn visit(
            graph: &Vec<Vec<usize>>,
            node: usize,
            visited: &mut Vec<bool>,
            result: &mut Vec<usize>,
        ) {
            if visited[node] {
                return;
            }

            visited[node] = true;
            result.push(node);

            for &next in &graph[node] {
                visit(graph, next, visited, result);
            }
        }

        visit(&self.adj, start, &mut visited, &mut result);

        result
    }
}
```

**广度优先搜索 DFS**

广度优先搜索算法（Breadth-first search），又译作宽度优先搜索，或横向优先搜索，是一种图形搜索算法。简单的说，BFS是从根节点开始，沿着树的宽度遍历树的节点。如果所有节点均被访问，则算法中止。广度优先搜索的实现一般采用open-closed表。 

BFS是一种暴力搜索算法，目的是系统地展开并检查图中的所有节点，以找寻结果。换句话说，它并不考虑结果的可能地址，彻底地搜索整张图，直到找到结果为止。BFS并不使用经验法则算法。 

Rust使用队列实现BFS：

```
use std::collections::VecDeque;

impl Graph {
    fn bfs(&self, start: usize) -> Vec<usize> {
        let mut visited = vec![false; self.adj.len()];
        let mut queue = VecDeque::new();
        let mut result = Vec::new();

        visited[start] = true;
        queue.push_back(start);

        while let Some(node) = queue.pop_front() {
            result.push(node);

            for &next in &self.adj[node] {
                if !visited[next] {
                    visited[next] = true;
                    queue.push_back(next);
                }
            }
        }

        result
    }
}
```

**DFS 和 BFS 的区别**

| 对比项           | DFS                  | BFS                |
| ---------------- | -------------------- | ------------------ |
| 中文名称         | 深度优先搜索         | 广度优先搜索       |
| 搜索方式         | 先深入一条路径       | 逐层扩展           |
| 常用实现         | 递归、栈             | 队列               |
| 是否需要 visited | 需要                 | 需要               |
| 适合场景         | 连通性、回溯、环检测 | 最短路径、层级搜索 |
| 无权图最短路径   | 不保证               | 可以保证           |
| 时间复杂度       | O(V + E)             | O(V + E)           |

简单理解：

```
DFS：一条路走到底，再回来
BFS：一圈一圈向外扩散
```

**环检测**

向图和无向图上的环可用深度优先搜索（DFS）探测：寻找一条连接当前顶点与之前顶点的边（它包含了一条后向边）。DFS跳过的所有后向边都属于某个环。无向图上，指向父节点的边不能算作后向边，但找到已经过的顶点意味着后向边的存在。找到n阶无向图上的环只需要O(n)时间。

许多拓扑排序算法也要探测环，因为它们将是拓扑排序的障碍。另外，若有向图被分为几个强连通分量，那么环只会存在于这些分量内，而不会连接，因为环本身就是强连接的。

对有向图，还可使用基于分布式信息的算法。其思路是，从一个顶点发出的信息可通过环回到这个顶点。分布式环检测算法十分适于在计算机集群上用分布式图处理系统来处理大规模的图。

环检测的应用如用wait-for graph检测并行系统的死锁。

在Rust中实现：

```
struct Graph {
    adj: Vec<Vec<usize>>,
}

impl Graph {
    fn new(n: usize) -> Self {
        Self {
            adj: vec![Vec::new(); n],
        }
    }

    fn add_edge(&mut self, a: usize, b: usize) {
        self.adj[a].push(b);
        self.adj[b].push(a);
    }

    fn has_cycle(&self) -> bool {
        let mut visited = vec![false; self.adj.len()];

        fn dfs(
            graph: &Vec<Vec<usize>>,
            node: usize,
            parent: Option<usize>,
            visited: &mut Vec<bool>,
        ) -> bool {
            visited[node] = true;

            for &next in &graph[node] {
                if !visited[next] {
                    if dfs(graph, next, Some(node), visited) {
                        return true;
                    }
                } else if Some(next) != parent {
                    return true;
                }
            }

            false
        }

        for start in 0..self.adj.len() {
            if !visited[start] && dfs(&self.adj, start, None, &mut visited) {
                return true;
            }
        }

        false
    }
}
```

**连通分量**

在图论中，分量（Component）又称为连通分量、元件、或分支，是一个无向子图，在分量中的任何两个顶点都可以经由该图上的边抵达另一个顶点，且没有任何一边可以连到其他子图的顶点。例如右图中的无向图可以分成3个无向子图，也就是3个分量。没有与任何其他顶点相连的单一顶点也可以算是一个分量。 

连通分量常用于：

- 统计社交网络中的群组数量
- 判断地图中有多少个独立区域
- 统计岛屿数量
- 判断网络是否完全连通
- 图像中的区域识别

Rust中实现：

```fn count_components(graph: &[Vec<usize>]) -> usize {
    fn count_components(graph: &[Vec<usize>]) -> usize {
    let mut visited = vec![false; graph.len()];
    let mut count = 0;

    fn dfs(
        graph: &[Vec<usize>],
        node: usize,
        visited: &mut [bool],
    ) {
        if visited[node] {
            return;
        }

        visited[node] = true;

        for &next in &graph[node] {
            dfs(graph, next, visited);
        }
    }

    for start in 0..graph.len() {
        if !visited[start] {
            count += 1;
            dfs(graph, start, &mut visited);
        }
    }

    count
}
```



### 基础排序算法

**冒泡排序**（Bubble Sort）又称为泡式排序，是一种简单的排序算法。它重复地走访过要排序的数列，一次比较两个元素，如果它们的顺序错误就把它们交换过来。走访数列的工作是重复地进行直到没有再需要交换，也就是说该数列已经排序完成。这个算法的名字由来是因为越小的元素会经由交换慢慢“浮”到数列的顶端。 

冒泡排序算法的运作如下：

1. 比较相邻的元素。如果第一个比第二个大，就交换它们两个。
2. 对每一对相邻元素作同样的工作，从开始第一对到结尾的最后一对。这步做完后，最后的元素会是最大的数。
3. 针对所有的元素重复以上的步骤，除了最后一个。
4. 持续每次对越来越少的元素重复上面的步骤，直到没有任何一对数字需要比较。

```
fn bubble_sort(nums: &mut [i32]) {
    let n = nums.len();

    for i in 0..n {
        let mut swapped = false;

        for j in 0..n - 1 - i {
            if nums[j] > nums[j + 1] {
                nums.swap(j, j + 1);
                swapped = true;
            }
        }

        if !swapped {
            break;
        }
    }
}
```

**复杂度**

| 情况       | 时间复杂度 |
| ---------- | ---------- |
| 最好情况   | O(n)       |
| 平均情况   | O(n²)      |
| 最坏情况   | O(n²)      |
| 空间复杂度 | O(1)       |

**选择排序**（Selection sort）是一种简单直观的排序算法。它的工作原理如下。首先在未排序序列中找到最小（大）元素，存放到排序序列的起始位置，然后，再从剩余未排序元素中继续寻找最小（大）元素，然后放到已排序序列的末尾。以此类推，直到所有元素均排序完毕。 

**特点**

- 实现简单
- 可以提前结束
- 稳定排序
- 效率较低

```
fn selection_sort(nums: &mut [i32]) {
    let n = nums.len();

    for i in 0..n {
        let mut min_index = i;

        for j in i + 1..n {
            if nums[j] < nums[min_index] {
                min_index = j;
            }
        }

        nums.swap(i, min_index);
    }
}
```

**复杂度**

| 情况       | 时间复杂度 |
| ---------- | ---------- |
| 最好情况   | O(n²)      |
| 平均情况   | O(n²)      |
| 最坏情况   | O(n²)      |
| 空间复杂度 | O(1)       |

即使数组已经有序，选择排序仍然需要扫描剩余元素，因此不会像优化后的冒泡排序一样提前结束。

**特点**

- 交换次数较少
- 实现简单
- 原地排序
- 通常不稳定
- 无论数据是否有序，复杂度都是 O(n²)

**插入排序**（Insertion Sort）是一种简单直观的排序算法。它的工作原理是通过构建有序序列，对于未排序数据，在已排序序列中从后向前扫描，找到相应位置并插入。插入排序在实现上，通常采用in-place排序（即只需用到 O ( 1 )的额外空间的排序），因而在从后向前扫描过程中，需要反复把已排序元素逐步向后挪位，为最新元素提供插入空间。 

简单来说就是将数组分为有序部分和无序部分，每次从无序部分取出一个元素，插入到有序部分的正确位置。

```fn insertion_sort(nums: &mut [i32]) {
    for i in 1..nums.len() {
        let current = nums[i];
        let mut j = i;

        while j > 0 && nums[j - 1] > current {
            nums[j] = nums[j - 1];
            j -= 1;
        }

        nums[j] = current;
    }
}
```

**复杂度**

| 情况       | 时间复杂度 |
| ---------- | ---------- |
| 最好情况   | O(n)       |
| 平均情况   | O(n²)      |
| 最坏情况   | O(n²)      |
| 空间复杂度 | O(1)       |

当数组基本有序时，插入排序的效率比较高。

**特点**

- 实现简单
- 稳定排序
- 原地排序
- 适合数据量较小或基本有序的数据
- 最坏情况下效率较低

**快速排序**（Quicksort），又称分区交换排序（partition-exchange sort），是一种排序算法，最早由东尼·霍尔提出。在平均状况下，排序 n 个项目要  O ( nlog n ) 次比较。在最坏状况下则需要 O (n^2) 次比较，但这种状况并不常见。事实上，快速排序O ( nlog ⁡n )通常明显比其他算法更快，因为它的内部循环可以在大部分的架构上很有效率地达成。 

快速排序使用分治法策略来把一个序列分为较小和较大的2个子序列，然后递归地排序两个子序列。

步骤为：

1. 挑选基准值：从数列中挑出一个元素，称为“基准”，
2. 分割：重新排序数列，所有比基准值小的元素摆放在基准前面，所有比基准值大的元素摆在基准后面（与基准值相等的数可以到任何一边）。在这个分割结束之后，对基准值的排序就已经完成，
3. 递归排序子序列：递归地将小于基准值元素的子序列和大于基准值元素的子序列排序。

```fn quick_sort(nums: &mut [i32]) {
    fn quick_sort(nums: &mut [i32]) {
    if nums.len() <= 1 {
        return;
    }

    let pivot_index = partition(nums);

    let (left, right) = nums.split_at_mut(pivot_index);

    quick_sort(left);
    quick_sort(&mut right[1..]);
}

fn partition(nums: &mut [i32]) -> usize {
    let pivot_index = nums.len() - 1;
    let pivot = nums[pivot_index];

    let mut smaller_index = 0;

    for i in 0..pivot_index {
        if nums[i] <= pivot {
            nums.swap(smaller_index, i);
            smaller_index += 1;
        }
    }

    nums.swap(smaller_index, pivot_index);

    smaller_index
}
```

**复杂度**

| 情况     | 时间复杂度    |
| -------- | ------------- |
| 最好情况 | O(n log n)    |
| 平均情况 | O(n log n)    |
| 最坏情况 | O(n²)         |
| 额外空间 | 平均 O(log n) |

如果数组本身已经有序，而每次都选择最后一个元素作为基准值，就可能退化为O(n²)。

**快速排序的特点**

优点：

- 平均性能优秀
- 通常是原地排序
- 缓存友好
- 实际运行速度较快

缺点：

- 最坏情况可能达到 O(n²)
- 通常不是稳定排序
- 对基准值的选择比较敏感

**归并排序**（Merge sort），是建立在归并操作上的一种有效的排序算法,指的是将两个已经排序的序列合并成一个序列的操作。归并排序算法依赖归并操作。

**递归法（Top-down）**

1. 申请空间，使其大小为两个已经排序序列之和，该空间用来存放合并后的序列
2. 设置两个指针，最初位置分别为两个已经排序序列的起始位置
3. 比较两个指针所指向的元素，选择相对小的元素放入到合并空间，并移动指针到下一位置
4. 重复步骤3直到某一指针到达序列尾
5. 将另一序列剩下的所有元素直接复制到合并序列尾

**迭代法（Bottom-up）**

原理如下（假设序列共有n 个元素）：

1. 将序列每相邻两个数字进行归并操作，形成个序列，排序后每个序列包含两/一个元素
2. 若此时序列数不是1个则将上述序列再次归并，形成个序列，每个序列包含四/三个元素
3. 重复步骤2，直到所有元素排序完毕，即序列数为1

递归法和迭代法分别就是自顶向下和自定向上。

```
fn merge_sort(nums: &mut [i32]) {
    let n = nums.len();

    if n <= 1 {
        return;
    }

    let mid = n / 2;

    merge_sort(&mut nums[..mid]);
    merge_sort(&mut nums[mid..]);

    let mut merged = Vec::with_capacity(n);

    let mut left = 0;
    let mut right = mid;

    while left < mid && right < n {
        if nums[left] <= nums[right] {
            merged.push(nums[left]);
            left += 1;
        } else {
            merged.push(nums[right]);
            right += 1;
        }
    }

    while left < mid {
        merged.push(nums[left]);
        left += 1;
    }

    while right < n {
        merged.push(nums[right]);
        right += 1;
    }

    nums.copy_from_slice(&merged);
}
```

**复杂度**

| 情况     | 时间复杂度 |
| -------- | ---------- |
| 最好情况 | O(n log n) |
| 平均情况 | O(n log n) |
| 最坏情况 | O(n log n) |
| 额外空间 | O(n)       |

**归并排序的特点**

优点：

- 时间复杂度稳定
- 稳定排序
- 适合链表
- 适合外部排序
- 适合处理大文件

缺点：

- 需要额外的 O(n) 空间
- 对数组进行排序时，空间开销较大

**堆排序**（Heapsort）是指利用堆这种数据结构所设计的一种排序算法。堆是一个近似完全二叉树的结构，并同时满足堆的性质：即子节点的键值或索引总是小于（或者大于）它的父节点。 

在堆的数据结构中，堆中的最大值总是位于根节点（在优先队列中使用堆的话堆中的最小值位于根节点）。堆中定义以下几种操作：

- 最大堆调整（Max Heapify）：将堆的末端子节点作调整，使得子节点永远小于父节点
- 建立最大堆（Build Max Heap）：将堆中的所有数据重新排序
- 堆排序（HeapSort）：移除位在第一个数据的根节点，并做最大堆调整的递归运算

以升序排序为例，可以使用大根堆：

```
        9
       / \
      7   8
     / \
    3   5
```

大根堆的特点是：

> 每个父节点都不小于它的子节点。

因此，堆顶始终是当前最大元素。

堆排序的过程：

1. 将数组构建成大根堆。
2. 将堆顶最大值与数组末尾交换。
3. 缩小堆的范围。
4. 重新调整堆。
5. 重复执行。

```
fn heap_sort(nums: &mut [i32]) {
    let n = nums.len();

    if n <= 1 {
        return;
    }

    // 建立大根堆
    for i in (0..n / 2).rev() {
        sift_down(nums, i, n);
    }

    // 依次将最大值放到末尾
    for end in (1..n).rev() {
        nums.swap(0, end);
        sift_down(nums, 0, end);
    }
}

fn sift_down(nums: &mut [i32], mut root: usize, end: usize) {
    loop {
        let left = root * 2 + 1;

        if left >= end {
            break;
        }

        let right = left + 1;
        let mut larger = left;

        if right < end && nums[right] > nums[left] {
            larger = right;
        }

        if nums[root] >= nums[larger] {
            break;
        }

        nums.swap(root, larger);
        root = larger;
    }
}
```

**复杂度**

| 情况     | 时间复杂度 |
| -------- | ---------- |
| 最好情况 | O(n log n) |
| 平均情况 | O(n log n) |
| 最坏情况 | O(n log n) |
| 额外空间 | O(1)       |

堆排序不需要额外数组，因此空间复杂度为 O(1)。

**堆排序的特点**

优点：

- 时间复杂度稳定
- 不需要额外数组
- 适合空间受限的场景

缺点：

- 通常不是稳定排序
- 实际速度通常不如快速排序
- 实现复杂度较高

目前重温学习的六种排序，涵盖了从学习路径到小规模，再到通用排序算法，实际工作中的原则通常是，普通情况直接使用标准库排序；有稳定性、内存、Top K、整数范围或大文件等特殊需求时，再选择合适的专用算法。

## 图算法

### 最短路径

**最短路径**问题是图论研究中的一个经典算法问题，旨在寻找图（由结点和路径组成的）中两结点之间的最短路径。算法具体的形式包括：

- **确定起点的最短路径问题** - 也叫单源最短路问题，即已知起始结点，求最短路径的问题。在边权非负时适合使用Dijkstra算法，若边权为负时则适合使用Bellman-ford算法或者SPFA算法。
- **确定终点的最短路径问题** - 与确定起点的问题相反，该问题是已知终结结点，求最短路径的问题。在无向图中该问题与确定起点的问题完全等同，在有向图中该问题等同于把所有路径方向反转的确定起点的问题。
- **确定起点终点的最短路径问题** - 即已知起点和终点，求两结点之间的最短路径。
- **全局最短路径问题** - 也叫多源最短路问题，求图中所有的最短路径。适合使用Floyd-Warshall算法。

在无权图中，可以使用BFS求最短路径。因为BFS 按照距离起点的层级访问节点：

```
use std::collections::VecDeque;

fn shortest_distance(
    graph: &[Vec<usize>],
    start: usize,
    target: usize,
) -> Option<usize> {
    let mut distance = vec![None; graph.len()];
    let mut queue = VecDeque::new();

    distance[start] = Some(0);
    queue.push_back(start);

    while let Some(current) = queue.pop_front() {
        if current == target {
            return distance[current];
        }

        let current_distance = distance[current].unwrap();

        for &next in &graph[current] {
            if distance[next].is_none() {
                distance[next] = Some(current_distance + 1);
                queue.push_back(next);
            }
        }
    }

    None
}
```

**带权图中的最短路径**

如果每条边的权重不同，就不能直接使用 BFS。

例如：

```
A --1--> B --10--> D
 \                 ^
  ------3---------->
```

两条路径：

```
A -> B -> D：1 + 10 = 11
A -> D：3
```

虽然 `A -> B -> D` 经过的边更少或相同，但真正的最短路径应该比较权重：

```
A -> D
```

此时需要使用 Dijkstra 算法。

Dijkstra 适用于：

- 带权图
- 边权值不能为负数
- 图中可以有环

不适用于：

- 存在负权边
- 存在负权环

**Dijkstra**算法解决的是：从一个起点到图中所有节点的最短路径问题。我的理解这个算法就是维护一个距离数组：

```
dist[i] = 起点到节点 i 的当前最短距离
```

初始状态：

```
起点距离为 0
其他节点距离为无穷大
```

然后反复执行：

1. 选择当前距离最小的未处理节点。
2. 访问它的所有邻居。
3. 尝试更新邻居距离。
4. 如果找到更短路径，就更新距离。
5. 重复执行。

更新公式：

```
new_distance = dist[current] + edge_weight
```

如果：

```
new_distance < dist[next]
```

就更新：

```
dist[next] = new_distance
```

这个过程称为松弛。

Rust中实现：

```
use std::cmp::Reverse;
use std::collections::BinaryHeap;

#[derive(Clone, Copy)]
struct Edge {
    to: usize,
    weight: usize,
}

fn dijkstra(
    graph: &[Vec<Edge>],
    start: usize,
) -> Vec<usize> {
    let mut distance = vec![usize::MAX; graph.len()];
    let mut heap = BinaryHeap::new();

    distance[start] = 0;

    heap.push(Reverse((0, start)));

    while let Some(Reverse((current_distance, current))) =
        heap.pop()
    {
        if current_distance > distance[current] {
            continue;
        }

        for edge in &graph[current] {
            let new_distance =
                current_distance + edge.weight;

            if new_distance < distance[edge.to] {
                distance[edge.to] = new_distance;

                heap.push(Reverse((
                    new_distance,
                    edge.to,
                )));
            }
        }
    }

    distance
}
```

**最小生成树**

最小生成树（Minimum spanning tree）是最小权重生成树（Minimum weight spanning tree）的简称，是一个连通加权无向图中一棵权值最小的生成树。 一个连通图可能有多个生成树。当图中的边具有权值时，总会有一个生成树的边的权值之和小于或者等于其它生成树的边的权值之和。广义上而言，对于非连通无向图来说，它的每一连通分量同样有最小生成树，它们的并被称为最小生成森林。

以有线电视电缆的架设为例，若只能沿着街道布线，则以街道为边，而路口为顶点，其中必然有一最小生成树能使布线成本最低。 

**最短路径和最小生成树这两个概念非常容易混淆，最短路径是找两个指定节点之间的最短路线，最小生成树是用最低的总成本连接所有的节点。**

**Kruskal 算法**

克鲁斯克尔算法（Kruskal's algorithm）的核心思想是：

> 每次选择当前权重最小的边，只要加入后不会形成环，就将它加入生成树。

具体步骤是:

1.  新建图 G ， G 中拥有原图中相同的节点，但没有边
2.  将原图中所有的边按权值从小到大排序
3.  从权值最小的边开始，如果这条边连接的两个节点于图 G 中不在同一个连通分量中，则添加这条边到图 G 中
4.  重复3，直至图 G 中所有的节点都在同一个连通分量中

**Kruskal 的执行过程**

假设有以下边：

```
A-B：1
B-D：2
C-D：3
A-C：4
A-D：5
```

首先按权重排序：

```
1、2、3、4、5
```

依次选择：

**选择 A-B**

```
A ---- B
```

不会形成环，加入。

**选择 B-D**

```
A ---- B ---- D
```

不会形成环，加入。

**选择 C-D**

```
A ---- B ---- D
             |
             C
```

不会形成环，加入。

现在已经有 4 个节点和 3 条边：

```
节点数 - 1 = 3
```

算法结束。

**Kruskal 的 Rust 实现**

定义边：

```
#[derive(Clone, Copy, Debug)]
struct Edge {
    from: usize,
    to: usize,
    weight: i32,
}
```

实现 Kruskal：

```
fn kruskal(
    n: usize,
    mut edges: Vec<Edge>,
) -> Option<(i32, Vec<Edge>)> {
    edges.sort_by_key(|edge| edge.weight);

    let mut uf = UnionFind::new(n);
    let mut result = Vec::new();
    let mut total_weight = 0;

    for edge in edges {
        if uf.union(edge.from, edge.to) {
            total_weight += edge.weight;
            result.push(edge);

            if result.len() == n - 1 {
                break;
            }
        }
    }

    if result.len() == n - 1 {
        Some((total_weight, result))
    } else {
        None
    }
}
```

**Prim 算法**

普里姆算法（Prim's algorithm）是图论中的一种贪心算法，可在一个加权连通图中找到其最小生成树。意即由此算法搜索到的边子集所构成的树中，不但包括了连通图里的所有顶点，且其所有边的权值之和亦为最小。

Prim 的核心思想是：

> 从一个节点开始，每次选择连接当前生成树和外部节点的最小边。

它和 Dijkstra 有些相似，都会使用优先队列，但目标不同：

- Dijkstra：求起点到其他节点的最短路径
- Prim：构建连接所有节点的最小生成树

```
use std::cmp::Reverse;
use std::collections::BinaryHeap;

fn prim(graph: &[Vec<(usize, i32)>]) -> Option<i32> {
    let n = graph.len();

    if n == 0 {
        return Some(0);
    }

    let mut visited = vec![false; n];
    let mut heap = BinaryHeap::new();
    let mut total_weight = 0;
    let mut visited_count = 0;

    heap.push(Reverse((0, 0)));

    while let Some(Reverse((weight, node))) = heap.pop() {
        if visited[node] {
            continue;
        }

        visited[node] = true;
        visited_count += 1;
        total_weight += weight;

        for &(next, edge_weight) in &graph[node] {
            if !visited[next] {
                heap.push(Reverse((edge_weight, next)));
            }
        }
    }

    if visited_count == n {
        Some(total_weight)
    } else {
        None
    }
}
```

### 贪心算法

贪心算法（greedy algorithm），又称贪婪算法，是一种在每一步选择中都采取在当前状态下最好或最优（即最有利）的选择，从而希望导致结果是最好或最优的算法。比如在旅行推销员问题中，如果旅行员每次都选择最近的城市，那这就是一种贪心算法。

贪心算法的核心思想是：

> 每一步都选择当前看起来最优的方案，希望最终得到全局最优解。

也就是说，贪心算法只关注当前选择，不回头修改之前的决定。

```
当前最优选择
    ↓
继续做下一步最优选择
    ↓
最终得到结果
```

但要注意：

> 局部最优不一定能得到全局最优。

所以贪心算法不是遇到“每次选最大的”就可以直接使用，必须证明它的选择策略是正确的。

**零钱兑换例子：**

假设硬币面额为：

```
[1, 5, 10, 20]
```

兑换金额 36。

每次尽量选择最大的硬币：

```
20 + 10 + 5 + 1 = 36
```

一共 4 枚硬币。

对于人民币、美元等常见货币系统，这种贪心策略通常有效。

Rust 实现：

```
fn coin_change_greedy(coins: &[i32], mut amount: i32) -> Vec<i32> {
    let mut coins = coins.to_vec();
    coins.sort_by(|a, b| b.cmp(a));

    let mut result = Vec::new();

    for coin in coins {
        while amount >= coin {
            amount -= coin;
            result.push(coin);
        }
    }

    if amount == 0 {
        result
    } else {
        Vec::new()
    }
}
```

### 动态规划

动态规划（Dynamic programming）常常适用于有重叠子问题和最优子结构性质的问题，动态规划方法所耗时间往往远少于朴素解法。

动态规划背后的基本思想非常简单。大致上，若要解一个给定问题，我们需要解其不同部分（即子问题），再根据子问题的解以得出原问题的解。 

经典例子就是01背包问题。

0-1 背包问题是：有一个容量有限的背包，每件物品只能选一次，目标是在不超过容量的情况下，让总价值最大。

例如：

```
背包容量：5

物品 A：重量 2，价值 3
物品 B：重量 3，价值 4
物品 C：重量 4，价值 5
```

可以选择 A 和 B：

```
总重量：2 + 3 = 5
总价值：3 + 4 = 7
```

这里的“0-1”意思是每件物品只有两种选择：

```
0：不放入背包
1：放入背包一次
```

不能把同一件物品放多次；能重复放的是“完全背包问题”。

动态规划的核心状态是：

```
dp[i][j]
```

表示“只考虑前 `i` 件物品，背包容量为 `j` 时，能得到的最大价值”。

```
fn knapsack_01(weights: &[usize], values: &[i32], capacity: usize) -> i32 {
    let mut dp = vec![0; capacity + 1];

    for (&weight, &value) in weights.iter().zip(values.iter()) {
        for current_capacity in (weight..=capacity).rev() {
            let not_take = dp[current_capacity];
            let take = dp[current_capacity - weight] + value;

            dp[current_capacity] = not_take.max(take);
        }
    }

    dp[capacity]
}
```
