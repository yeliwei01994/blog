## 问题与反思

昨天，坤元视算拉取代码进行 AI 分镜功能测试时，我发现生成的分镜卡片在退出账号、重新登录后会消失，之前生成的内容没有保留下来。看到这个现象后，我初步判断问题可能和数据持久化有关，于是在单独的分支上做了修改。

后续我只简单询问相关情况，但没有继续把问题的复现条件、影响范围和具体原因确认清楚，也没有及时说明自己发现的问题和已经做过的修改。因为当时没有继续跟进，我对这项改动也没有保持足够的关注。晚上提交代码时，我没有认真检查当前分支和本地改动，就把代码推到了 dev 仓库。

今天检查的时候看到这次改动时，发现这段后端的修改，我也检查了仓库，看到这项本地修改已经进入 dev。在没有充分确认根因、也没有和相关沟通的情况下，我不应该仅凭最初的判断就决定修改后端。

今天进一步排查后发现，分镜卡片重新登录后消失确实是一个 BUG，但它会因浏览器不同而表现不同：在谷歌浏览器中没有发现问题，在 IE 和火狐中会出现。这个结果说明我最初发现的现象并不是无效反馈，也说明排查问题时不能只在一种浏览器里确认结果。目前可以确认问题存在且表现与浏览器环境有关，具体原因和合适的修复方式还需要根据稳定的复现结果继续分析。

发现卡片没有保留后，我很快把原因指向数据持久化，并开始修改，却没有先整理稳定的复现步骤，也没有覆盖不同浏览器进行对比。开发中的第一判断只能作为排查方向，不能直接当成已经确认的根因。

涉及后端或公共代码的改动会影响其他人的工作，也可能改变现有数据流程。即使我认为自己是在修复 BUG，也应该先把问题现象、复现条件、初步判断和计划改动的范围讲清楚，一起确认处理方向。问题是否真实存在、改动是否合适、能否进入 dev 分支，是需要分别确认的事情。

今天确认它确实是一个 BUG，并不能抵消昨天提交流程上的疏忽。应该先经过必要的流程。开发协作不是只对最后的代码结果负责，也要对修改过程、影响范围和信息同步负责。

提交代码前如果没有确认当前分支、工作区改动和暂存内容，就可能把未确认的本地代码带入 dev。公共仓库是团队共同使用的代码基线，误推代码会给其他同事带来额外的检查和维护成本，也会让分支状态变得不清晰。

提交前应该看清楚当前在哪个分支、具体有哪些文件变化、暂存区里包含什么，以及最终要推送到哪里。

以后遇到类似问题，涉及后端、公共模块或公共分支的修改，我应该先汇报问题和修改范围，确认处理方向后再继续实施。修改过程中如果发现判断或方案发生变化，也会及时同步，避免其他人基于过时的信息继续处理。

提交代码前，我也应该逐项检查当前分支、本地改动、暂存区内容和目标仓库，确保提交的内容与已经确认的工作一致。如果发现有不属于本次任务或尚未确认的改动，会先将它从本次提交范围中排除，并确认处理方式后再提交。遇到不确定的情况，我会先停下来检查清楚，不凭记忆或习惯直接推送。

开发工作不仅是发现问题后尽快写代码，也包括充分验证、及时汇报和规范提交。即使问题最后被证明确实存在，处理过程也必须遵守团队协作流程。我需要对自己的代码和公共分支负责，避免因为一时疏忽把未经确认的修改推入 dev。后续我会把问题确认和提交前检查真正落实到每次开发中，不让类似的流程问题再次发生。

## 补充学习：高斯模糊

当初听到高斯模糊这个词时，我其实马上有点反应，觉得很耳熟。查了一下才想起来，它本质上就是以前学过的传统图像处理算法之一高斯平滑只是叫法不一样了。以前学习这些算法时，想到的应用基本都是图片处理和降噪，没想到现在做前端页面设计也会用到同一个方法。

从图像处理的角度看，高斯模糊就是用一个按高斯分布生成的卷积核，在图像上逐个位置滑动。卷积核通常是一小块矩阵，中心位置的权重最大，离中心越远权重越小。每移动到一个像素，就把周围像素的颜色值分别乘上卷积核对应位置的权重，再把结果加起来，作为输出图像在这个位置的新像素值。输出像素不是只取原图对应的那个点，而是综合附近像素算出来的加权平均。

以前学图像算法时，高斯平滑常用于减弱图像中的细小噪声，或者在边缘检测、计算机视觉等处理之前先平滑图像，减少细节和高频变化对后续步骤的干扰。它会让画面整体变得平滑，但噪声变弱的同时，边缘和纹理也可能一起变软。

没想到这类传统图像算法也能直接用于前端视觉效果。在网页里，filter: blur(6px) 会模糊元素自身渲染出的内容；backdrop-filter: blur(12px) 则会模糊元素后面的画面，常用于半透明导航栏、弹窗背景或玻璃质感面板。

```css
.image {
  filter: blur(6px);
}

.glass-panel {
  background: rgb(255 255 255 / 65%);
  backdrop-filter: blur(12px);
}
```

这次补充让我把以前学过的图像处理知识和现在的前端工作联系起来了。看到高斯模糊时觉得耳熟，原来不是因为名字相似，而是它确实就是熟悉的高斯平滑，生成卷积核，在像素周围做加权计算。以前它主要出现在图片降噪和传统视觉算法里，现在则可以通过 CSS 变成页面中的背景层次和视觉氛围。底层原理相同，使用场景变了。
