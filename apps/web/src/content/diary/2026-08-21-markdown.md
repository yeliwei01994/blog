### Markdown 基本语法学习笔记


#### 一、Markdown 是什么

Markdown 是一种轻量级标记语言。它通过少量易读的符号描述文档结构，让纯文本同时具备较好的可读性和排版能力。

例如，下面这段文字即使不经过渲染，也能看出标题、列表和代码的层次：

```markdown
# 项目说明

这是项目的简介。

## 安装步骤

1. 安装依赖
2. 修改配置
3. 启动项目
```

Markdown 文件通常使用 `.md` 作为扩展名，可以被转换成 HTML，也可以用于生成 PDF、技术文档、博客文章、README 文件和学习笔记。它的重点不是让作者花大量时间调整字体和间距，而是让作者专注于内容本身。

#### 二、标题语法

Markdown 使用 `#` 表示标题，`#` 的数量决定标题级别，最多可以使用六级标题：

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

渲染后，一级标题最大，六级标题最小。通常建议遵循下面的结构：

```markdown
# 文章主题

## 第一部分
### 第一部分中的小节

## 第二部分
### 第二部分中的小节
```

##### 标题的使用建议

1. 一篇文章通常只保留一个一级标题，用来表示文章主题。
2. 不要为了让文字变大而滥用标题，强调文字应使用粗体。
3. 不要跳过层级，例如从 `##` 直接跳到 `####`。
4. 标题符号和文字之间最好保留一个空格：`## 正确写法`。
5. 标题前后最好留一个空行，能够减少不同编辑器之间的解析差异。

错误示例：

```markdown
#正确但不推荐
##错误示例
```

推荐写法：

```markdown
# 正确写法
## 推荐写法
```

#### 三、段落与换行

普通文字直接书写即可。Markdown 通常以空行区分段落：

```markdown
这是第一段。它可以包含多句话，直到遇到空行。

这是第二段。空行会让内容变成新的段落。
```

##### 段内换行

如果只是想在同一段中换一行，可以在上一行末尾添加两个空格，再按回车：

```markdown
第一行文字。  
第二行文字。
```

也可以使用 HTML 的 `<br>` 标签：

```markdown
第一行文字。<br>
第二行文字。
```

不过，不同平台对单个回车的处理方式并不完全一致。为了让文章在博客、GitHub 和其他编辑器中保持稳定，建议使用空行表示新段落，只有确实需要同一段内换行时才使用两个空格或 `<br>`。

#### 四、强调文字

##### 斜体

使用一对星号或下划线包裹文字：

```markdown
*斜体文字*
_斜体文字_
```

效果：*斜体文字*。

斜体适合表示补充说明、术语的特别强调或外文词语，但不建议整段使用斜体，否则阅读压力会比较大。

##### 粗体

使用两对星号或下划线包裹文字：

```markdown
**粗体文字**
__粗体文字__
```

效果：**粗体文字**。

粗体更适合突出结论、关键词和操作步骤。例如：**提交代码前必须先运行测试**。

##### 粗斜体

同时使用三颗星号：

```markdown
***粗斜体文字***
```

效果：***粗斜体文字***。

##### 删除线

删除线不是最早的基础 Markdown 语法，但很多编辑器都支持使用两个波浪线：

```markdown
~~已经删除的内容~~
```

效果：~~已经删除的内容~~。

它适合表示修改前的内容、已经废弃的方案或自我纠正，不建议把删除线当作普通强调手段。

#### 五、列表语法

##### 无序列表

无序列表可以使用 `-`、`*` 或 `+`：

```markdown
- Redis
- MySQL
- Rust
```

效果：

- Redis
- MySQL
- Rust

同一组列表最好统一使用同一种符号，不要在同一层级混用 `-`、`*` 和 `+`。

##### 有序列表

有序列表使用数字加英文句点：

```markdown
1. 安装依赖
2. 修改配置
3. 启动服务
```

效果：

1. 安装依赖
2. 修改配置
3. 启动服务

有些 Markdown 编辑器会自动修正编号，因此即使全部写成 `1.`，渲染时也可能显示为连续的数字。不过为了提高源文件的可读性，手动写出正确编号仍然是更好的习惯。

##### 嵌套列表

在列表项前增加两个或四个空格，可以表示子列表：

```markdown
- 前端
  - HTML
  - CSS
  - JavaScript
- 后端
  - Java
  - Go
  - Rust
```

嵌套列表的缩进必须保持一致。如果某一项缩进太少，编辑器可能会把它解析成新的一级列表。

##### 任务列表

任务列表常用于记录待办事项，写法是方括号加空格或 `x`：

```markdown
- [ ] 学习标题和段落语法
- [x] 整理代码块语法
- [ ] 完成文章发布
```

效果：

- [ ] 学习标题和段落语法
- [x] 整理代码块语法
- [ ] 完成文章发布

任务列表属于许多平台支持的扩展语法。如果某个平台没有显示复选框，通常仍会把它当作普通列表展示。

#### 六、引用块

使用 `>` 表示引用：

```markdown
> Markdown 的重点是表达内容结构，而不是复杂的视觉排版。
```

效果：

> Markdown 的重点是表达内容结构，而不是复杂的视觉排版。

引用块也可以包含多段内容：

```markdown
> 这是引用的第一段。
>
> 这是引用的第二段。
```

通过增加 `>` 可以实现嵌套引用：

```markdown
> 外层引用
>> 内层引用
```

引用适合用于记录资料原文、提示重要信息、补充背景说明或展示命令执行结果。引用内容最好注明来源，不要把整篇外部文章直接复制进来。

#### 七、代码语法

##### 行内代码

使用一对反引号包裹短代码：

```markdown
使用 `git status` 可以查看当前工作区状态。
```

效果：使用 `git status` 可以查看当前工作区状态。

行内代码适合表示命令、变量名、函数名、文件名、配置项和键盘按键，例如 `package.json`、`npm install` 和 `PORT`。

##### 多行代码块

使用三个反引号包裹多行代码：

````markdown
```
const message = 'Hello Markdown';
console.log(message);
```
````

代码块的开头可以写语言名称，以便编辑器进行语法高亮：

````markdown
```javascript
const message = 'Hello Markdown';
console.log(message);
```
````

常见语言标识包括：

```text
javascript、typescript、python、java、go、rust、css、html、json、yaml、bash、sql
```

展示命令时，可以使用 `bash`：

```bash
pnpm install
pnpm dev
```

展示 JSON 时，可以使用 `json`：

```json
{
  "name": "markdown-note",
  "version": "1.0.0"
}
```

代码块中的内容会按照原样显示，因此不要在代码块内部额外添加不必要的缩进。代码块前后也建议各留一个空行。

#### 八、链接语法

标准链接的写法是：

```markdown
[Markdown 基本语法](https://markdown.com.cn/basic-syntax/)
```

效果：[Markdown 基本语法](https://markdown.com.cn/basic-syntax/)。

链接文字应该尽量说明目标内容，不建议把一长串 URL 直接作为链接文字。比如“查看 Markdown 基本语法”比“点击这里”更容易理解，也更有利于无障碍阅读。

##### 给链接增加标题

可以在 URL 后面增加可选标题：

```markdown
[Markdown 教程](https://markdown.com.cn/basic-syntax/ "查看基本语法")
```

##### 自动链接

部分 Markdown 编辑器会自动识别完整 URL：

```markdown
https://markdown.com.cn/basic-syntax/
```

也可以使用尖括号明确表示自动链接：

```markdown
<https://markdown.com.cn/basic-syntax/>
<example@example.com>
```

#### 九、图片语法

图片语法和链接非常相似，只是在前面增加一个感叹号：

```markdown
![图片说明](https://example.com/image.png)
```

其中，方括号里的文字叫作替代文本。当图片无法加载，或读者使用屏幕阅读器时，替代文本可以帮助读者理解图片内容。

也可以为图片添加标题：

```markdown
![Markdown 标志](https://example.com/markdown.png "Markdown Logo")
```

图片路径可以是网络地址，也可以是相对于当前 Markdown 文件的本地路径：

```markdown
![项目目录结构](./images/project-tree.png)
```

使用本地图片时要注意文件名大小写、相对路径层级和部署后的目录结构。文章在本地能显示，并不代表发布到网站后一定能显示。

#### 十、表格语法

表格通常用于展示字段、对比结果或配置说明：

```markdown
| 语法 | 作用 |
| --- | --- |
| `#` | 创建标题 |
| `-` | 创建列表 |
| `>` | 创建引用 |
```

效果：

| 语法 | 作用 |
| --- | --- |
| `#` | 创建标题 |
| `-` | 创建列表 |
| `>` | 创建引用 |

通过冒号可以控制对齐方式：

```markdown
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| 内容 | 内容 | 内容 |
```

表格中的竖线如果属于正文内容，需要使用反斜杠转义：

```markdown
| 命令 | 说明 |
| --- | --- |
| `a \| b` | 使用管道符连接两个值 |
```

表格适合简短内容。如果单元格里需要放很长的段落、代码块或复杂列表，建议改用多个小节，避免表格在手机上难以阅读。

#### 十一、分隔线

使用三个或更多的连字符、星号或下划线可以创建分隔线：

```markdown
---
```

也可以写成：

```markdown
***
___
```

分隔线适合区分文章中两个相对独立的部分，例如正文和附录。不要频繁使用分隔线，否则文章会被切割得过于零散。

#### 十二、转义字符

Markdown 中有一些特殊字符具有语法含义。如果希望它们按照普通文字显示，可以在前面添加反斜杠：

```markdown
\*这不是斜体\*
\# 这不是标题
\[这不是链接\]
```

常见需要转义的字符包括：

```text
\\ 反斜杠
\` 反引号
\* 星号
\_ 下划线
\{ \} 花括号
\[ \] 方括号
\( \) 小括号
\# 井号
\+ 加号
\- 连字符
\. 句点
\! 感叹号
\| 管道符
```

例如，如果想在文章中展示标题写法，而不是让它真的变成标题，可以写成：

```markdown
\# 这段文字会显示井号
```

#### 十三、内嵌 HTML

Markdown 支持在文档中混合使用部分 HTML：

```html
<br>
<span>这是一段 HTML 文本。</span>
```

也可以使用 HTML 控制图片宽度或增加特定结构，但不同平台对 HTML 的支持不完全一致。因此，日常写作时应优先使用 Markdown 自身的语法，只有在 Markdown 无法满足需求时再使用 HTML。

需要特别注意的是，某些网站会过滤危险或不安全的 HTML 标签和属性。不要在不清楚平台安全策略的情况下嵌入脚本、事件属性或外部组件。

#### 十四、推荐的文章写作流程

写一篇 Markdown 文章时，可以按照下面的顺序组织：

1. 先确定一个清晰的一级标题。
2. 使用二级标题拆分主要内容。
3. 每个小节先用普通段落解释概念。
4. 使用列表整理多个并列要点。
5. 使用代码块展示可以复制的代码或命令。
6. 使用引用块突出注意事项或外部资料。
7. 使用链接补充官方文档和参考资料。
8. 发布前检查标题层级、空行、代码闭合、图片路径和表格格式。

不要一开始就纠结字体、颜色和复杂布局。先把内容结构写清楚，再根据发布平台支持的扩展语法进行优化，通常能够获得更稳定的结果。
