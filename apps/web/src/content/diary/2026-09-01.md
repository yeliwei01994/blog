### Graph Engineering 到底是什么？

#### 先用一句话解释

**Graph Engineering，就是把一个复杂任务拆成许多“工作小块”，再设计它们之间的合作路线，让多个 AI、工具和人一起完成任务。**

可以把它想成学校里的小组作业：

- 一个同学负责查资料
- 一个同学负责计算
- 一个同学负责写作
- 一个同学负责检查
- 老师最后审核

如果只告诉一个同学：

> “你自己把所有事情都做好。”

他可能会忘记事情、算错数字、没有检查，或者做到一半迷路。

Graph Engineering 做的事情，就是先画出一张“谁负责什么、下一步交给谁”的地图。

它像给一支 AI 小队画作战地图：

```
总负责人
  ↓
搜索 Agent ─┐
分析 Agent ──┼→ 写作 Agent → 检查 Agent → 人类确认
数据 Agent ─┘
```

#### Graph Engineering 的核心组成

##### 1. 节点：谁来做事？

节点可以代表一个工作角色。

例如做新闻研究：

```
搜索员
事实核查员
数据分析员
写作者
编辑
```

每个角色最好只负责一类事情。

这样做的好处是：

- 工作目标更清楚
- 每个角色更容易检查
- 出错时容易找到责任步骤
- 可以让不同模型负责不同难度的任务

例如：

- 搜索员擅长找资料
- 数据员擅长计算
- 写作者擅长表达
- 审核员擅长发现错误

------

##### 2. 边：下一步交给谁？

边就是“工作路线”。

例如：

```
搜索资料 → 检查来源 → 分析资料
```

它表示：

> 搜索员完成以后，结果先交给事实核查员，再交给分析员。

边还可以带条件。

例如：

```
资料可信？
  ├── 是 → 继续分析
  └── 否 → 重新搜索
```

这样 AI 就不会不管资料真假，直接往下做。

------

##### 3. 状态：现在做到哪了？

状态就是任务的“记事本”。

里面可能记录：

- 已经完成的步骤
- 找到的资料
- 当前结论
- 还没解决的问题
- 哪些地方可能出错
- 哪个 Agent 正在工作
- **最后更新时间**

例如：

```
{
  "任务": "写市场报告",
  "搜索": "已完成",
  "数据分析": "进行中",
  "资料来源": 12,
  "发现的问题": 2,
  "是否可以发布": false
}
```

如果没有状态，多个 Agent 就像几个人共用一张白纸，却不知道别人写了什么。

------

##### 4. 共享信息：大家怎么交换结果？

一个 Agent 做完工作后，必须把结果交给下一个 Agent。

但不能把所有内容都无脑传过去。

更好的做法是只传：

- 必要的资料
- 关键结论
- 数据来源
- 当前任务状态
- 需要下一个人处理的问题

这叫“控制上下文”。

如果把所有聊天记录、所有文件、所有搜索结果都塞给每个 Agent，系统会：

- 变慢
- 变贵
- 更容易迷路
- 更容易抓错重点

------

##### 5. 检查器：谁来找错误？

Graph Engineering 很重视“检查”。

例如：

```
写作 Agent → 事实检查 Agent
```

事实检查 Agent 要问：

- 这个数字是真的吗？
- 这个来源支持这个说法吗？
- 有没有把两个概念混在一起？
- 有没有漏掉重要信息？
- 有没有自己编造内容？

对于重要任务，还可以安排多个检查器：

```
写初稿
  ├── 事实检查
  ├── 逻辑检查
  ├── 格式检查
  └── 安全检查
```

最后再把检查结果交给编辑。

------

##### 6. 人类节点：什么时候必须让人决定？

不是所有事情都应该由 AI 自动完成。

例如：

- 发邮件给客户
- 删除数据库内容
- 发布文章
- 转账
- 修改生产系统
- 做医疗或法律相关决定

可以设计成：

```
AI 准备操作 → 人类确认 → 系统执行
```

人类就是图中的一个特殊节点。

Graph Engineering 的价值之一，就是让人清楚看到：

> AI 做到了哪一步，下一步为什么需要我批准。

------

##### 7. 终点：什么时候算完成？

很多 AI 系统的问题是：

> 一直做，一直改，却不知道什么时候应该停。

所以图里必须有明确的“完成条件”。

例如：

- 所有问题都已经回答
- 每个重要数字都有来源
- 检查器没有发现严重错误
- 人类已经批准
- 总花费没有超过预算
- 最多重试三次
- 在规定时间内完成

没有停止条件，Agent 可能会陷入死循环。

#### 常见的 Graph Engineering 结构

##### 1. 顺序结构

一个步骤接一个步骤：

```
A → B → C → D
```

适合：

- 翻译
- 文档处理
- 简单审批
- 固定流程

例如：

```
读取文件 → 提取重点 → 写摘要 → 检查格式
```

------

##### 2. 并行结构

多个工作同时进行：

```
          ┌→ 搜索市场资料 ─┐
开始 ─────┼→ 搜索竞争对手 ─┼→ 汇总
          └→ 搜索财务数据 ─┘
```

适合：

- 不同资料可以同时搜索
- 多个文件可以同时处理
- 多个 Agent 可以分别研究不同方向

好处是速度更快。

但要注意：并行任务最后必须有人负责“汇总”，否则大家各说各的。

------

##### 3. 分支结构

根据情况选择不同路线：

```
任务是什么？
  ├── 写文章 → 写作路线
  ├── 查数据 → 数据路线
  └── 改代码 → 编程路线
```

这就像学校老师看到不同题目，安排不同同学处理。

------

##### 4. 检查—重做结构

```
完成工作 → 检查
             ├── 合格 → 下一步
             └── 不合格 → 返回修改
```

这是非常重要的一种结构。

但要设置最大次数：

```
最多修改 3 次
```

否则会出现：

```
修改 → 检查 → 修改 → 检查 → 无限修改
```

------

##### 5. 总负责人结构

```
                 ┌→ Agent A
总负责人 Agent ──┼→ Agent B
                 └→ Agent C
                       ↓
                  总负责人汇总
```

总负责人负责：

- 拆分任务
- 分配工作
- 收集结果
- 发现缺口
- 决定下一步

这很像班长安排同学完成小组作业。

------

##### 6. 专家互相讨论结构

```
研究员 A ⇄ 研究员 B
    ↓        ↓
       裁判 Agent
```

多个 Agent 可以提出不同答案，再由另一个 Agent 比较。

适合：

- 复杂研究
- 代码审查
- 方案比较
- 风险判断

但它也可能浪费很多时间和费用，所以不能什么事情都使用这种结构。

### 数据结构：从数组到图

数据结构是计算机科学中的基础概念，主要研究如何组织和存储数据，以及如何高效地访问、修改和管理这些数据。

不同的数据结构适用于不同的场景。选择合适的数据结构，往往能够显著提升程序的执行效率。

#### 一、什么是数据结构

按照数据之间的组织关系，数据结构通常可以分为以下几类：

- 线性数据结构
- 树形数据结构
- 图结构
- 哈希结构
- 特殊数据结构

其中，数组、链表、栈和队列属于线性结构；二叉树、堆和字典树属于树形结构；图则用于描述更加复杂的网络关系。

#### 二、线性数据结构

##### 1. 数组

数组是一种连续存储数据的线性结构。

```
[10][20][30][40][50]
```

数组中的元素通常通过下标访问，例如：

```
int value = arr[2];
```

由于数组中的元素连续存储，因此可以根据首地址和下标直接计算出目标元素的位置，访问时间复杂度为 O(1)。

| 操作       | 时间复杂度 |
| ---------- | ---------- |
| 按下标访问 | O(1)       |
| 查找元素   | O(n)       |
| 末尾插入   | O(1)       |
| 中间插入   | O(n)       |
| 删除元素   | O(n)       |

数组的优点是支持随机访问、内存连续、缓存利用率较高，并且实现简单。

它的缺点是中间插入和删除需要移动大量元素，静态数组长度固定，扩容时可能需要重新分配内存。

动态数组，例如 Java 中的 `ArrayList`、Python 中的 `list`，本质上仍然是数组，只是在容量不足时自动扩容。

##### 二维数组

二维数组可以理解为由多个一维数组组成的数据结构，通常用于表示表格、矩阵或网格。

```
[
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]
```

二维数组中的元素通过两个下标访问：

```
matrix[行下标][列下标]
```

例如：

```
System.out.println(matrix[1][2]); // 输出 6
```

这里的 `matrix[1][2]` 表示第 2 行、第 3 列的元素。

二维数组通常使用嵌套循环进行遍历：

```
for (int i = 0; i < matrix.length; i++) {
    for (int j = 0; j < matrix[i].length; j++) {
        System.out.println(matrix[i][j]);
    }
}
```

其中：

- 外层循环负责遍历每一行
- 内层循环负责遍历当前行中的每一列

二维数组的访问时间复杂度仍然是 O(1)，遍历全部元素的时间复杂度为 O(m × n)，其中 m 表示行数，n 表示列数。

##### 二维数组的常见应用

二维数组常用于：

- 数学矩阵
- 棋盘和地图
- 图像像素
- 游戏地图
- 表格数据
- 动态规划
- 迷宫问题
- 图的邻接矩阵

例如，可以使用二维数组表示一个简单的棋盘：

```
char[][] board = {
    {'X', 'O', 'X'},
    {'O', 'X', 'O'},
    {'X', ' ', 'O'}
};
```

二维数组还可以表示地图，其中：

- `0` 表示可以通行
- `1` 表示障碍物

```
0 0 1
0 1 0
0 0 0
```

需要注意的是，二维数组不一定要求每一行长度相同。例如：

```
int[][] arr = {
    {1, 2},
    {3, 4, 5},
    {6}
};
```

这种结构称为不规则数组或锯齿数组。它本质上是一个数组中的每个元素又指向一个一维数组，因此每一行可以拥有不同的长度。

##### 2. 链表

链表由多个节点组成，每个节点包含数据和指向其他节点的指针。

```
[10 | next] -> [20 | next] -> [30 | null]
```

与数组不同，链表中的节点不要求连续存储。

链表主要包括以下几种类型：

- 单向链表：每个节点只保存下一个节点的地址。
- 双向链表：每个节点同时保存前驱节点和后继节点。
- 循环链表：最后一个节点指向第一个节点，形成一个环。

双向链表可以表示为：

```
null <- [10] <-> [20] <-> [30] -> null
```

| 操作           | 时间复杂度 |
| -------------- | ---------- |
| 按位置访问     | O(n)       |
| 查找元素       | O(n)       |
| 头部插入       | O(1)       |
| 已知节点后插入 | O(1)       |
| 已知节点删除   | O(1)       |

数组适合频繁访问，链表适合频繁插入和删除。如果程序经常通过下标访问元素，数组通常更合适；如果数据结构经常发生插入和删除，链表可能更有优势。

##### 3. 栈

栈是一种后进先出，也就是 LIFO 的数据结构。

```
入栈：1 -> 2 -> 3

出栈：3 -> 2 -> 1
```

栈只能从一端进行操作，这一端称为栈顶。

常见操作包括：

- `push`：入栈
- `pop`：出栈
- `peek`：查看栈顶元素

这些操作通常都是 O(1)。

栈的常见应用场景包括：

- 函数调用和递归
- 括号匹配
- 表达式求值
- 深度优先搜索
- 浏览器后退
- 编辑器撤销操作

函数调用栈就是栈结构的典型应用。当一个函数调用另一个函数时，系统会将当前函数的执行状态压入栈中，函数执行结束后再从栈顶恢复。

##### 4. 队列

队列是一种先进先出，也就是 FIFO 的数据结构。

```
入队：1 -> 2 -> 3

出队：1 -> 2 -> 3
```

队列通常从队尾插入元素，从队首删除元素。

常见操作包括：

- `enqueue`：入队
- `dequeue`：出队
- `front`：查看队首元素

队列能够保证先提交的任务先执行，因此经常用于需要维护处理顺序的场景。

常见应用包括：

- 任务调度
- 消息队列
- 打印任务管理
- 广度优先搜索
- 网络请求排队

##### 5. 双端队列

双端队列，英文为 Deque，允许从队首和队尾同时进行插入和删除。

```
队首 <-> [1][2][3] <-> 队尾
```

双端队列兼具栈和队列的特点：

- 只操作一端时，可以作为栈使用。
- 两端分别操作时，可以作为队列使用。

常见应用场景包括：

- 滑动窗口问题
- 单调队列
- 任务调度
- 需要两端操作的缓存结构

#### 三、哈希与集合结构

##### 1. 哈希表

哈希表通过哈希函数将键映射到数组中的某个位置。

```
key -> hash(key) -> 数组下标
```

例如：

```
"name" -> 3
"age"  -> 7
```

哈希表通常以键值对的形式保存数据：

```
{
    "name": "Tom",
    "age": 20
}
```

| 操作 | 平均时间复杂度 |
| ---- | -------------- |
| 插入 | O(1)           |
| 查找 | O(1)           |
| 删除 | O(1)           |

不同的键可能经过哈希函数计算后得到相同的位置，这种情况称为哈希冲突。

常见的哈希冲突解决方式有：

1. 链地址法：每个数组位置维护一个链表或其他容器。
2. 开放地址法：发生冲突后，继续寻找其他可用位置。

当哈希表中的元素过多时，通常需要扩容，以降低冲突概率。

哈希表常用于：

- 字典
- 集合
- 缓存
- 数据统计
- 数据去重
- 数据库中的哈希索引

##### 2. 集合

集合用于保存不重复的数据。

```
{1, 2, 3, 4}
```

常见操作包括：

- 添加元素
- 删除元素
- 判断元素是否存在
- 求交集
- 求并集
- 求差集

##### 3. 映射

映射用于保存键值对：

```
用户 ID -> 用户信息
```

集合和映射底层通常使用哈希表或平衡树实现。

- 哈希表实现：查找速度快，但通常无序。
- 平衡树实现：数据有序，但操作复杂度一般为 O(log n)。

#### 四、树形数据结构

##### 1. 树的基本概念

树是一种具有层级关系的数据结构。

```
        A
       / \
      B   C
     / \
    D   E
```

树中的常见概念包括：

- 根节点：树的起始节点
- 父节点：某个节点的上一级节点
- 子节点：某个节点的下一级节点
- 叶子节点：没有子节点的节点
- 深度：节点距离根节点的层数
- 高度：节点到最深叶子节点的距离

树结构广泛应用于文件系统、数据库索引、编译器和搜索系统。

##### 2. 二叉树

二叉树中的每个节点最多有两个子节点，分别称为左子节点和右子节点。

```
      1
     / \
    2   3
```

二叉树常见的遍历方式包括：

- 前序遍历：根节点 -> 左子树 -> 右子树
- 中序遍历：左子树 -> 根节点 -> 右子树
- 后序遍历：左子树 -> 右子树 -> 根节点
- 层序遍历：从上到下、从左到右逐层访问，通常使用队列实现

##### 3. 二叉搜索树

二叉搜索树，也称 BST，满足以下规则：

```
左子树中的所有节点值 < 根节点值
右子树中的所有节点值 > 根节点值
```

例如：

```
        8
       / \
      3   10
     / \
    1   6
```

对二叉搜索树进行中序遍历，可以得到有序的数据序列。

当树保持平衡时，查找、插入和删除的时间复杂度通常为 O(log n)。如果树退化成链表，复杂度则会退化为 O(n)。

##### 4. 平衡树

为了避免二叉搜索树退化，出现了平衡树。

常见的平衡树包括：

- AVL 树
- 红黑树
- 伸展树
- Treap

平衡树通过旋转等操作控制树的高度，从而保证查找、插入和删除操作具有较稳定的效率。

红黑树是工程中比较常见的一种平衡树，例如：

- Java 的 `TreeMap`
- Java 的 `TreeSet`
- C++ 的 `map`
- C++ 的 `set`

##### 5. 堆

堆是一种特殊的完全二叉树，常用于实现优先队列。

小根堆要求父节点的值小于或等于子节点：

```
       1
      / \
     3   5
```

大根堆要求父节点的值大于或等于子节点：

```
       9
      / \
     7   5
```

| 操作               | 时间复杂度 |
| ------------------ | ---------- |
| 查看最大值或最小值 | O(1)       |
| 插入元素           | O(log n)   |
| 删除最大值或最小值 | O(log n)   |
| 建堆               | O(n)       |

堆常用于：

- 优先队列
- 堆排序
- Top K 问题
- 定时任务
- Dijkstra 最短路径算法

##### 6. 字典树

字典树，也叫 Trie，专门用于处理字符串和前缀查询。

例如，存储以下单词：

```
cat
car
dog
```

`cat` 和 `car` 会共享 `ca` 这一部分路径。

如果字符串长度为 L，那么 Trie 的插入、查找和删除操作通常都是 O(L)。

Trie 的常见应用包括：

- 自动补全
- 搜索提示
- 拼写检查
- 前缀匹配
- IP 路由匹配

Trie 的主要缺点是空间占用可能较大。

##### 7. B 树和 B+ 树

B 树是一种多路平衡搜索树，一个节点可以拥有多个子节点。

B+ 树是 B 树的变体，常用于数据库索引和文件系统。

B+ 树的特点包括：

- 非叶子节点主要用于存储索引
- 数据通常存放在叶子节点
- 叶子节点之间通常通过链表连接
- 适合范围查询
- 可以减少磁盘 I/O

数据库中的索引通常使用 B+ 树，而不是普通二叉搜索树，主要原因是 B+ 树的高度更低，并且一次磁盘读取可以加载更多索引数据。

#### 五、图与连通性结构

图是一种用于描述对象之间关系的数据结构。图由若干个顶点和连接顶点的边组成，通常记作：

```
G = (V, E)
```

其中：

- `V` 表示顶点集合
- `E` 表示边集合

例如，社交网络中的用户可以看作顶点，用户之间的好友关系可以看作边：

```
A ---- B
|      |
C ---- D
```

这里的 `A、B、C、D` 是顶点，连接它们的线是边。

与数组、链表、树等结构不同，图中的数据不一定具有明确的层级或线性顺序，因此图特别适合表示复杂的网络关系。

常见应用包括：

- 地图和导航系统
- 社交网络
- 网络拓扑
- 推荐系统
- 任务依赖关系
- 课程先修关系
- 物流和交通网络
- 游戏中的地图与路径

##### 1. 图的基本概念

图的数据结构包含一个有限（可能是可变的）的[集合](https://zh.wikipedia.org/wiki/集合_(计算机科学))作为**节点**集合，以及一个无序对（对应无向图）或有序对（对应有向图）的集合作为**边**（有向图中也称作**弧**）的集合。节点可以是图结构的一部分，也可以是用整数下标或[引用](https://zh.wikipedia.org/wiki/引用_(程序设计))表示的外部实体。

图的数据结构还可能包含和每条边相关联的数值（edge value），例如一个标号或一个数值（即权重，weight；表示花费、容量、长度等）。

###### 顶点

顶点，也叫节点，表示图中的一个对象。

例如：

- 一个用户
- 一个城市
- 一个网页
- 一个任务
- 一个设备

###### 边

边表示两个顶点之间的关系。

例如：

- 两个用户是好友
- 两座城市之间存在道路
- 两个任务之间存在依赖关系
- 两个网页之间存在链接

###### 度

一个顶点连接的边数称为该顶点的度。

例如：

```
    A
    |
B --C-- D
    |
    E
```

节点 `C` 连接了 `A、B、D、E`，因此它的度为 4。

在有向图中，度还可以分为：

- 入度：指向该顶点的边数
- 出度：从该顶点指出的边数

------

##### 2. 图的常见类型

###### 无向图

无向图中的边没有方向。

```
A ---- B
```

这表示 A 与 B 相连，同时也表示 B 与 A 相连。

例如，好友关系通常可以使用无向图表示，因为如果 A 是 B 的好友，通常 B 也是 A 的好友。

###### 有向图

有向图中的边具有方向。

```
A ----> B
```

这表示可以从 A 到达 B，但不一定能够从 B 到达 A。

例如：

- 网页之间的超链接
- 任务之间的依赖关系
- 微博关注关系
- 城市之间的单向道路

###### 带权图

带权图中的每条边都有一个权值。

```
A --5-- B
```

权值可以表示：

- 距离
- 时间
- 费用
- 网络延迟
- 风险
- 运输成本

例如，在地图中，顶点表示城市，边表示道路，边上的权值表示道路长度。

###### 不带权图

不带权图中的边没有具体权值，通常只表示两个顶点之间是否存在连接。

在不带权图中，边的默认权值通常可以认为是 1。

###### 连通图

如果图中的任意两个顶点之间都存在路径，那么这个图称为连通图。

```
A ---- B ---- C
```

在这个图中，A 可以通过 B 到达 C，因此它是连通的。

如果图中存在互不相连的部分，则称为非连通图。

###### 完全图

如果任意两个不同的顶点之间都存在边，则称为完全图。

例如：

```
A ----- B
|\     /|
| \   / |
|  \ /  |
C ----- D
```

完全图中的边数量较多，随着顶点数量增加，存储成本也会迅速增加。

###### 有向无环图

有向无环图通常简称 DAG，英文为 Directed Acyclic Graph。

它是一种有方向但不存在环路的图。

```
A -> B -> C
     |
     v
     D
```

DAG 常用于表示具有先后顺序的任务，例如：

- 编译任务依赖
- 课程先修关系
- 项目流程
- 软件包依赖
- 数据处理流程

拓扑排序只能应用于有向无环图。

------

##### 3. 图的存储方式

图的存储方式主要有邻接矩阵、邻接表和边集数组。

###### 邻接矩阵

邻接矩阵使用二维数组表示顶点之间的连接关系。

假设有三个顶点 `A、B、C`：

```
A ---- B
 \    /
   C
```

可以使用如下矩阵表示：

```
    A  B  C
A   0  1  1
B   1  0  1
C   1  1  0
```

其中：

- `1` 表示两个顶点之间存在边
- `0` 表示不存在边

如果是带权图，则矩阵中可以保存边的权值：

```
    A  B  C
A   0  5  2
B   5  0  3
C   2  3  0
```

邻接矩阵的空间复杂度为：

```
O(V²)
```

其中 `V` 表示顶点数量。

优点是判断两个顶点之间是否存在边非常快，时间复杂度为 O(1)。

缺点是即使图中边很少，也需要分配完整的二维数组，因此比较浪费空间。

邻接矩阵适合：

- 顶点数量较少
- 边比较多
- 需要频繁判断两点是否相连
- 表示完全图或稠密图

###### 邻接表

邻接表为每个顶点保存一个相邻顶点列表。

例如：

```
A -> B, C
B -> A, C
C -> A, B
```

添加一条边：

```
graph[a].add(b);
graph[b].add(a); // 无向图需要添加反向边
```

邻接表的空间复杂度为：

```
O(V + E)
```

其中：

- `V` 表示顶点数量
- `E` 表示边数量

邻接表适合：

- 顶点数量较多
- 边相对较少
- 稀疏图
- 需要遍历某个顶点的所有邻居

在实际开发和算法题中，邻接表通常比邻接矩阵更加常用。

###### 边集数组

边集数组直接保存所有边。

```
[
  (A, B, 5),
  (A, C, 2),
  (B, C, 3)
]
```

每条边通常包含：

- 起点
- 终点
- 权值

边集数组适合：

- Kruskal 最小生成树算法
- 需要按照权值排序的场景
- 图的边数量比较重要的场景

------

##### 4. 图的遍历

图的遍历是指按照一定规则访问图中的所有顶点。

最常见的两种遍历算法是：

- 深度优先搜索 DFS
- 广度优先搜索 BFS

------

##### 5. 深度优先搜索 DFS

DFS 的全称是 Depth-First Search，即深度优先搜索。

它的基本思想是：

> 从一个顶点出发，沿着一条路径不断深入，直到无法继续前进时再回溯。

例如：

```
        A
       / \
      B   C
     / \
    D   E
```

从 A 开始进行 DFS，可能的访问顺序是：

```
A -> B -> D -> E -> C
```

DFS 通常使用递归或栈实现。

###### 递归实现思路

```
void dfs(int node) {
    if (visited[node]) {
        return;
    }

    visited[node] = true;

    for (int next : graph[node]) {
        dfs(next);
    }
}
```

其中 `visited` 数组用于记录顶点是否已经访问过。

如果不使用 `visited` 数组，在存在环的图中可能会出现无限递归。

###### DFS 的复杂度

使用邻接表时：

```
时间复杂度：O(V + E)
空间复杂度：O(V)
```

其中：

- 每个顶点最多访问一次
- 每条边最多检查一次或两次

###### DFS 的应用

DFS 常用于：

- 判断图是否连通
- 查找路径
- 检测图中是否存在环
- 解决迷宫问题
- 统计连通分量
- 拓扑排序
- 解决岛屿数量问题

------

##### 6. 广度优先搜索 BFS

BFS 的全称是 Breadth-First Search，即广度优先搜索。

它的基本思想是：

> 从一个顶点开始，先访问距离为 1 的顶点，再访问距离为 2 的顶点，逐层向外扩展。

例如：

```
        A
       / \
      B   C
     / \
    D   E
```

从 A 开始进行 BFS，访问顺序通常是：

```
A -> B -> C -> D -> E
```

BFS 通常使用队列实现。

###### 伪代码

```
void bfs(int start) {
    Queue<Integer> queue = new LinkedList<>();
    boolean[] visited = new boolean[n];

    queue.offer(start);
    visited[start] = true;

    while (!queue.isEmpty()) {
        int current = queue.poll();

        for (int next : graph[current]) {
            if (!visited[next]) {
                visited[next] = true;
                queue.offer(next);
            }
        }
    }
}
```

###### BFS 的复杂度

使用邻接表时：

```
时间复杂度：O(V + E)
空间复杂度：O(V)
```

###### BFS 的应用

BFS 特别适合解决：

- 无权图最短路径
- 最少步数问题
- 社交网络中的关系层级
- 二叉树层序遍历
- 状态空间搜索
- 迷宫最短路径

在无权图中，BFS 第一次访问到某个顶点时，所经过的边数通常就是从起点到该顶点的最短距离。

------

##### 7. DFS 和 BFS 的区别

| 对比项                 | DFS                  | BFS                |
| ---------------------- | -------------------- | ------------------ |
| 中文名称               | 深度优先搜索         | 广度优先搜索       |
| 常用实现               | 递归、栈             | 队列               |
| 搜索方式               | 先深入再回溯         | 逐层扩展           |
| 适合问题               | 连通性、回溯、环检测 | 最短路径、最少步数 |
| 是否保证无权图最短路径 | 不保证               | 保证               |
| 空间复杂度             | O(V)                 | O(V)               |

简单来说：

- 想尽可能深入一条路径，可以考虑 DFS。
- 想寻找距离起点最近的目标，可以考虑 BFS。

------

##### 8. 图中的路径和环

###### 路径

路径是指从一个顶点到另一个顶点经过的顶点序列。

```
A -> B -> D
```

表示从 A 到 D 存在一条路径。

###### 环

如果从某个顶点出发，沿着边行走后又回到了这个顶点，就形成了环。

```
A -> B -> C -> A
```

环在不同场景中的含义不同：

- 依赖关系中出现环，可能导致任务无法执行
- 有向图中检测环，可以判断是否能够进行拓扑排序
- 路由网络中的环可能造成数据包循环

DFS 可以用于检测图中是否存在环。

------

##### 9. 拓扑排序

拓扑排序用于处理有向无环图中的先后依赖关系。

例如：

```
学习编程 -> 学习数据结构 -> 学习算法
```

拓扑排序结果必须满足：

> 如果存在边 A -> B，那么 A 必须排在 B 前面。

常见实现方式有：

- DFS
- BFS + 入度

使用 BFS 实现拓扑排序时，通常采用以下步骤：

1. 统计每个节点的入度。
2. 将入度为 0 的节点加入队列。
3. 取出队首节点，并删除它指向的边。
4. 如果某个节点的入度变为 0，则加入队列。
5. 重复执行，直到队列为空。

如果最终没有处理完所有顶点，说明图中存在环，无法完成拓扑排序。

###### 拓扑排序的应用

- 课程安排
- 软件包安装顺序
- 编译任务调度
- 项目任务依赖
- 数据处理流程

------

##### 10. 最短路径

最短路径问题是图中的经典问题，目标是寻找两个顶点之间代价最小的路径。

不同类型的图需要使用不同的算法。

###### BFS

适用于无权图，或者所有边权值相同的图。

时间复杂度通常为：

```
O(V + E)
```

###### Dijkstra 算法

适用于边权值非负的带权图。

Dijkstra 算法通常配合优先队列和堆使用。

它的基本思想是：

1. 从起点开始。
2. 每次选择当前距离最小的顶点。
3. 使用该顶点更新其相邻顶点的距离。
4. 重复执行，直到所有顶点处理完成。

适用场景包括：

- 地图导航
- 网络路由
- 物流路径规划

###### Bellman-Ford 算法

Bellman-Ford 可以处理带负权边的图，并且能够检测负权环，但效率通常低于 Dijkstra。

###### Floyd-Warshall 算法

Floyd-Warshall 用于求任意两个顶点之间的最短路径。

它适合顶点数量较少，但需要查询大量点对最短路径的场景。

------

##### 11. 最小生成树

最小生成树用于无向带权连通图。

它需要满足：

- 包含所有顶点
- 不存在环
- 边的总权值最小

常见算法有：

- Prim 算法
- Kruskal 算法

最小生成树可以用于：

- 设计网络线路
- 铺设通信电缆
- 建设道路系统
- 连接多个城市
- 构建低成本网络

Kruskal 算法通常与并查集一起使用，用于判断加入一条边后是否会形成环。

#### 六、如何选择合适的数据结构

| 需求                     | 推荐数据结构     |
| ------------------------ | ---------------- |
| 根据下标快速访问         | 数组             |
| 频繁插入和删除           | 链表             |
| 后进先出                 | 栈               |
| 先进先出                 | 队列             |
| 两端操作                 | 双端队列         |
| 快速键值查找             | 哈希表           |
| 有序数据查询             | 平衡树           |
| 快速获取最大值或最小值   | 堆               |
| 字符串前缀查询           | Trie             |
| 表示网络关系             | 图               |
| 维护连通分组             | 并查集           |
| 数据库索引               | B+ 树            |
| 区间查询和修改           | 线段树、树状数组 |
| 缓存淘汰                 | LRU              |
| 节省空间判断元素是否存在 | 位图、布隆过滤器 |
